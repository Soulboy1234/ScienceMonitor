# 计划：2026-04-09_v1_2_1备份与v1_3_0大检查

## 目的 / 大图景
- 先把当前累计改动记录为 `v1.2.1`，作为大检查前的稳定备份点。
- 在此基础上对功能、代码、文档和目录进行一次系统性大检查，确认当前项目是否处于可发布状态。
- 仅在功能正确前提下做低风险优化，提升可读性、安全性、稳定性和代码熵控制质量。
- 最终只有在所有 gate 通过时，才记录 `v1.3.0`。

## 背景与定位
- 当前工作树累积了多轮 UI、harness、文档治理和标签参考统一改动，尚未收束成正式版本。
- 项目已经具备 `doctor`、`harness-check`、`maintenance-check`、`golden-eval`、`real-eval`、UI 审查和文档审查等治理能力。
- 这轮的任务不是继续扩新功能，而是把已有改动系统性检查、修正和收口。

## 工作范围
- 当前工作树的版本记录、发布记录和 tag 管理。
- 代码功能、文档准确性、目录摆放、治理链路和 UI 的全量检查。
- 低风险代码优化、熵治理和必要的文档纠偏。
- 最终版本 `v1.3.0` 的记录条件评估与执行。

## 非目标
- 不引入新的大型业务功能。
- 不做历史输出迁移。
- 不做超出当前改动边界的大规模重构。
- 不在检查未完成前提前记录 `v1.3.0`。

- 先确认当前工作树、版本和现有治理状态。

1. 盘点 `git status`、现有 tag、最新 gate 状态，建立这轮计划。

4. 汇总发现并执行低风险优化，必要时拆分模块、修正文档或收紧治理规则。
5. 跑 `doctor`、`entropy-check`、`harness-check`、`maintenance-check`、`pytest`。
