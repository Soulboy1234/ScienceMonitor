# 计划：2026-04-09_UI细化第八轮

## 目的 / 大图景
- 修复周报页在窄窗口下的布局崩坏问题。
- 把“窄视口可读性”纳入 UI harness 审核，避免视觉回归再次漏检。

## 背景与定位
- 当前 harness 能校验页面结构、关键片段和基础交互，但没有覆盖窄宽度下的布局稳定性。
- 用户在周报页发现面板宽度压缩后中文逐字竖排，说明现有 UI 审核只做了静态 HTML 检查，没有做视口级布局检查。

## 工作范围
- `src/sciencemonitor/config_ui_page_sections.py`
- `src/sciencemonitor/ui_assets/config_ui.css`
- `src/sciencemonitor/config_ui_review.py`
- `tests/test_config_ui.py`
- `tests/test_config_ui_review.py`

## 非目标
- 不重做整套 UI 信息架构。
- 不修改周报业务生成逻辑。
- 不做版本发布或 GitHub 同步。

## 计划中的工作

## 具体步骤
1. 让周报页在窄宽度下避免 3:1 硬压缩导致卡片过窄。
2. 调整表单内部网格，让字段在窄宽度时自动改单列。
3. 在 UI review 里补窄宽度布局规则，并在测试中锁定这类回归。
4. 跑校验并归档计划。

## 发现与意外
- 当前 harness 的 UI 审核只覆盖结构和关键片段，没有真正做浏览器窄视口渲染检查。
- 周报页的 `3:1` 首行布局在宽度继续缩小时会把中文标题压成逐字竖排，这类问题仅靠 HTML 结构测试看不出来。

## 决策记录
- 不引入重型截图对比链路，先在 CSS 和 UI review 中显式锁定窄视口断点规则。
- 周报页在 `1380px` 以下改为上下堆叠，在 `1100px` 以下整页行布局改单列，优先保证可读性。

## 结果与复盘
- 周报页窄窗口下不再保持 `3:1` 硬压缩，页面会自动切换为更稳的单列/上下布局。
- `config_ui_review` 现在会检查窄视口所依赖的 CSS 断点和关键类名，避免这类回归再次悄悄通过 harness。
- 这次修复后，UI harness 仍然不是完整视觉回归测试，但已经补上了本次问题对应的稳定性护栏。
