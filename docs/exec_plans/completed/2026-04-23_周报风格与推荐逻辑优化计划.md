# 计划：2026-04-23_周报风格与推荐逻辑优化

## 目的 / 大图景
- 重构周报中的“今日概览”“文章推荐”“主题推荐”文案生成逻辑，使其更接近 `log/report_update/report_new_design.md` 的目标风格。
- 收紧“与当前工作相关的重点”和“对当前工作的可能启发”的匹配逻辑，避免把仅边缘相关的文章推到用户当前主线里。
- 去掉主题分析中的兜底废话和泛化句式，让“主题推荐”只围绕具体研究对象或科学问题展开。

## 背景与定位
- 当前 `2026-04-17 周报` 已经过一轮标签纠偏，但周报文案仍有明显问题：主题分析句式僵硬、当前工作匹配过宽、推荐理由泛化。
- 用户已经提供了新的周报设计文档，当前任务是先把程序与 harness 调整到新风格，再基于真实周报继续迭代。
- 这轮以周报逻辑与审核为边界，不重新抓取文献，不重做单篇总结内容。

## 工作范围
- `src/sciencemonitor/reporting.py`
- `src/sciencemonitor/reporting_support.py`
- 与周报审核相关的测试和必要的规则文档
- 重新生成 `2026-04-17 周报`

## 非目标
- 不修改 UI 布局
- 不重新设计 formal / pending 标签体系
- 不处理新的抓取源或新的深度解读输出

## 进度
- [x] 步骤 1：对照新设计梳理周报现有生成逻辑，收紧“主题推荐”和“当前工作相关”匹配规则
- [x] 步骤 2：修改周报生成与审核逻辑，补测试并验证文案稳定性
- [x] 步骤 3：重建 `2026-04-17 周报`，执行 harness 检查并归档计划

## 计划中的工作
- 先用新设计文档反查当前周报生成函数的分段职责和问题点。
- 再收紧主题推荐、推荐论文和当前工作相关段落的内容生成逻辑。
- 对容易退化成兜底废话的段落补审核或回退规则。
- 用现有 `auto` 单篇总结重建周报，直接检查真实输出是否符合新风格。

## 具体步骤
1. 读取设计文档和 `reporting` 相关函数，列出当前周报的结构偏差和文案退化点。
2. 修改主题聚类、偏好命中、推荐理由和期刊汇总生成逻辑，避免泛主题和重复废话。
3. 补对应测试，覆盖“主题推荐无泛主题”“当前工作相关匹配不过宽”“推荐文本避免兜底废话”。
4. 重新生成 `2026-04-17 周报`，人工核对关键段落。
5. 运行 `pytest`、`harness-check`，完成后归档计划。

## 发现与意外
- 当前周报中的低质量问题不只来自推荐逻辑，也来自 LLM 主题分析返回的兜底句式；需要在展示层再做一次本地审查，不能直接信任 `topic_insights`。
- `harness-check` 暴露出两个 `auto` 文件里残留旧 alias 标签，说明周报链路调整后仍需顺手跑一次 tag output review。

## 决策记录
- 先收紧规则法与周报审核，再考虑是否需要扩大 LLM 参与周报写作；当前优先保证稳定、可解释、低熵。
- “主题推荐”优先依赖具体主题 bucket 和单篇一句话总结，不允许退回到“该文主要涉及……”这类弱分析句式。
- “与当前工作相关的重点”和“对当前工作的可能启发”不再依赖宽松的研究偏好关键词匹配，改为报告层的高门槛直接命中规则。
- `主题推荐` 对两篇文章组成的宽泛对象簇加了额外抑制，避免把 `高能粒子/电子`、`太阳/日球层`、`地磁` 这类过宽对象硬拉成共同主题。

## 结果与复盘
- 已完成：
  - 收紧了周报中的当前工作相关匹配，避免背景性提及被当成直接相关。
  - 增加了主题推荐的弱主题过滤，并对低质量 LLM 主题分析自动回退到本地摘要。
  - 规范化了周报中的残留英文短语，例如 `thermospheric forcing`。
  - 重建了 `2026-04-17 周报`，并同步更新了周报 golden fixture。
- 当前残留：
  - “推荐论文”的推荐理由仍偏模板化，后续可以继续改成更具体的内容性推荐理由。
  - “各期刊主题汇总”里的具体论文推荐仍偏长，后续可继续压缩展示层。
