# 计划：2026-04-11_UI视觉审查与token坐标修复

## 目的 / 大图景
- 把 UI 视觉审查从“固定检查两个页面”升级为“按改动范围选择页面，必要时覆盖整个 UI”。
- 修复总览页 token 图的纵轴刻度错位和横轴日期溢出问题，让图表读数和视觉位置一致。

## 背景与定位
- 当前 `config_ui_visual_review.py` 固定截图总览和周报，不能根据改动范围动态决定审查页面。
- 这会导致两类问题：
  - 改了其他页面，但视觉审查没有覆盖到。
  - 只改局部页面，却总是默认跑固定页面，粒度不合理。
- 当前 token 图的纵轴标题和刻度共用同一网格容器，导致纵轴文字和网格线错位。
- 横轴日期标签在右侧会超出面板。

## 计划中的工作
- 先梳理视觉审查入口和 harness 调用链。
- 再修 token 图 DOM / CSS。
- 最后补回归测试并重启面板验证。

## 具体步骤
1. 为视觉审查增加目标页面集合与改动文件推断逻辑。
2. 让 harness 在本地根据当前改动文件选择要审查的 UI 页面。
3. 拆分 token 图纵轴标题与刻度容器，修复网格和刻度对应关系。
4. 调整横轴标签布局，避免右侧日期超出面板。
5. 更新测试、视觉审查、harness 检查，并重启面板。

## 发现与意外
- token 图纵轴错位的根因不是刻度算法，而是纵轴标题和刻度共享同一个网格容器，导致标题额外占据了一行布局空间。
- 横轴日期溢出的根因不是单纯宽度不足，而是 30 列网格里的可见日期标签仍按单列宽度渲染，必须改成锚点定位而不是逐列文本。

## 决策记录
- 视觉审查增加“显式目标页面”和“基于改动文件自动推断页面”两层入口；有明确目标时只审查目标页，无法推断时再回退到全量 UI。
- 当改动触及 `config_ui_page_sections.py`、`config_ui.css`、`config_ui.js` 这类共享 UI 文件时，视觉审查自动覆盖全部 5 个页面。
- token 图横轴日期标签改为锚点绝对定位，不再用 30 列逐格文本，保证标签可读且不越界。

## 结果与复盘
- `config_ui_visual_review.py` 现在支持按页面目标执行，并能根据当前改动文件自动选择总览、周报、深度解读、人工中转、设置中的相关页面。
- harness 已把当前工作区改动文件传入视觉审查，所以本次共享 UI 改动会自动扩展成 5 页视觉检查。
- 总览页 token 图已修复纵轴刻度与网格线对应关系，横轴日期也不再超出面板。
