# 计划：2026-04-28_期刊汇总显示名与深度解读UI反馈修复

## 目的 / 大图景
- 修复周报“各期刊主题汇总”标题显示策略，使其继续按同一期刊合并，但标题显示为期刊全称。
- 修复 UI 上传 PDF 后点击“开始深度解读”没有反馈的问题，让用户能明确看到任务已提交、正在运行或失败原因。

## 背景与定位
- 上一轮把周报期刊聚合统一成缩写，解决了 JGR 同一期刊被拆分的问题，但导致“各期刊主题汇总”的标题也变成缩写。
- 用户期望该章节标题保持全称，更利于阅读。
- UI 深度解读点击后无提示，可能是前端提交反馈、后端同步长任务或错误反馈链路存在缺口。

## 工作范围
- 周报期刊规范键与显示名逻辑。
- 周报当前输出的确定性修正。
- UI 深度解读提交交互反馈。
- 对应测试与 harness 检查。

## 非目标
- 不重写周报正文风格。
- 不改变深度解读报告内容标准。
- 不在本轮把深度解读改造成完整后台队列，除非定位表明同步执行无法提供基本反馈。

## 发现与意外
- 周报此前把“聚合键”和“显示标题”共用同一个缩写，能避免 JGR 被拆分，但会让章节标题退化成 `JGR.SP`。
- UI 深度解读返回状态只在总览错误卡中显示，用户留在深度解读页时看不到成功或失败提示。
- 上传 PDF 但不填 DOI/题目时，后端没有从原始文件名生成题名兜底，容易造成失败或输出标题不稳定。

## 决策记录
- 周报统计继续使用归一化键，例如 `JGR.SP`，展示层改用期刊全称。
- 深度解读 UI 不在本轮改为后台任务，只补“提交中”前端反馈和返回页状态提示。
- 上传 PDF 的单篇深度解读在题名为空时使用上传 PDF 原始文件名作为题名兜底。

## 结果与复盘
- 周报“各期刊主题汇总”的统计键继续使用 `JGR.SP` 等规范键，标题展示改为全称，当前 2026-04-28 周报和 `latest.md` 已同步修正。
- 深度解读 UI 增加提交中反馈、深度解读页内成功/失败提示，并在只上传 PDF 时使用原始文件名作为题名兜底。
- Golden daily_report fixture 已同步更新，避免合规的展示名变化被误判为漂移。
