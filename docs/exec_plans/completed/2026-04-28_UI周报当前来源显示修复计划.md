# 计划：2026-04-28_UI周报当前来源显示修复

## 目的 / 大图景
- 修复周报运行状态中“当前来源”在进入单篇总结阶段后仍显示旧来源的问题。
- 避免用户误以为抓取阶段还在运行或来源进度没有变化。

## 背景与定位
- 当前运行状态为 `summary_generation`，但 `current_source` 仍显示 `astronomy_astrophysics`。
- 根因是 UI 状态文件采用合并更新，抓取阶段的 `current_source` 没有在后续阶段清空。

## 工作范围
- UI 后台状态更新逻辑。
- 周报状态卡片渲染逻辑。
- 前端轮询状态更新逻辑。
- 对应 UI 测试。

## 非目标
- 不停止当前周报任务。
- 不修改周报生成内容和 LLM 逻辑。

## 进度
- [x] 步骤 1：修复状态字段清理
- [x] 步骤 2：修复 UI 条件显示
- [x] 步骤 3：补测试并验证

## 计划中的工作
- 只在抓取阶段显示 `current_source`。
- 进入单篇总结阶段后清空旧的 `current_source`。
- 当前运行态手动清掉旧字段，不打断 worker。

## 具体步骤
1. 修改 `config_ui_report_jobs.py` 的 `_update_status`。
2. 修改 `config_ui_result_cards.py` 和 `ui_assets/config_ui.js` 的显示条件。
3. 更新 `test_config_ui.py`。
4. 清理当前运行态里的旧 `current_source`。

## 发现与意外
- `current_source` 是抓取阶段字段，进入 `summary_generation` 后没有被清空，导致 UI 显示旧来源。
- 当前运行中的周报任务无需停止，只需把运行态里的旧 `current_source` 清空，后续 summary progress 会继续保持为空。

## 决策记录
- “当前来源”只表示抓取来源，不表示当前正在总结的文章来源。

## 结果与复盘

- 服务端渲染和前端轮询都只在抓取阶段显示“当前来源”。
- 当前运行态已清空旧 `current_source`，不打断正在运行的周报任务。
