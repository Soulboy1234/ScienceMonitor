## 发现与意外
- `doctor`、pytest、harness-check 均通过，功能侧没有发现阻断问题。
- `entropy-check` 初始失败，主要由近期功能增长后的维护预算滞后、函数内懒加载 import 被误报为 import cycle、少量未使用导入组成。
- 安全扫描未发现 `shell=True`、`eval()`、`os.system()` 这类高风险执行点；输出目录删除仍由 `safety.allow_output_deletions` 控制。

## 决策记录
- 本轮按“新的大版本”处理为 `v1.5.0`，不是补丁版本 `v1.4.1`。
- entropy 的 import-cycle 检查只统计顶层 import；函数内懒加载 import 用于破环和延迟加载，不应作为模块级循环计入。
- 维护预算更新到当前稳定基线附近，不通过机械拆文件制造“低行数”，避免把合理模块拆得更碎。
