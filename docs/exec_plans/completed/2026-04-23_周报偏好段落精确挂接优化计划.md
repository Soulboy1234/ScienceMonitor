# 计划：2026-04-23_周报偏好段落精确挂接优化

## 目的 / 大图景
- 把周报中“与当前工作相关的重点”“对当前工作的可能启发”后附的论文链接，从固定规则挂接改为 LLM 选择候选论文后再由本地监督校验。
- 让这两个段落的文本内容与后附论文真正对应，减少“文案在讲热层风，但挂接论文却是另外几篇”的不一致。

## 背景与定位
- 当前这两个段落已经改成 `LLM 输出 + 本地监督`，但末尾的“对应论文包括 / 可优先细读”仍是固定选前几篇相关论文。
- 这会导致文案和挂接论文之间不完全对齐，影响周报的可读性和可追溯性。
- 本轮只优化挂接方式，不改周报整体模板结构。

## 工作范围
- `src/sciencemonitor/llm.py`
- `src/sciencemonitor/llm_contracts.py`
- `src/sciencemonitor/reporting.py`
- `tests/test_reporting.py`

## 非目标
- 不调整 UI
- 不重构单篇总结内容
- 不处理标签体系的新规则

- [x] 步骤 2：在周报生成层接入“LLM 选论文 + 本地监督校验”的挂接逻辑，并补测试

## 计划中的工作
- 先让 LLM 显式返回这两个段落对应的论文索引列表。
- 再由本地监督过滤越界索引和弱相关索引。
- 最后用通过监督的索引来生成真正的 Obsidian 论文链接。

## 具体步骤
1. 扩展 `ReportAnalysis` 和 report schema，新增两个“论文索引列表”字段。
2. 更新 prompt，要求 LLM 对两个偏好段落分别返回对应论文编号。
3. 修改 `reporting.py`，优先用受监督的 LLM 索引挂接论文；不通过时回退到当前规则法。
4. 补测试，覆盖“索引被正确采用”和“非法/弱相关索引被回退”。
5. 重建 `2026-04-17 周报`，并运行 `pytest` 与 `harness-check`。

## 发现与意外
- 本轮第一次 `report_v6` 调用中，LLM 在 `preference_overview` 字段里返回了明显的协议残片和 JSON 修补话术；监督层已增加黑名单，避免类似坏输出进入周报正文。
- `report_v7` 之后，LLM 已能返回合理的偏好段落和论文索引，但 `auto` 目录中两个历史 alias 标签在每次周报重建后仍会回流，当前先做了输出级清理，后续需单独追源。

## 决策记录
- 继续保持“LLM 负责分析候选，本地负责监督和最终写出”的边界。
- 不让 LLM 直接输出 Markdown 链接，只返回索引，避免格式和路径漂移。

## 结果与复盘
- 已完成：
  - `ReportAnalysis` 新增 `preference_paper_indices` 和 `work_implication_paper_indices`。

  - `2026-04-17 周报` 已重建，两个偏好段落的后附论文不再固定取前几篇，而会优先采用监督通过的 LLM 论文编号。
