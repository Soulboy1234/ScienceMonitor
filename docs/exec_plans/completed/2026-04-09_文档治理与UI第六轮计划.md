# 计划：2026-04-09_文档治理与UI第六轮

## 目的 / 大图景
- 收紧可阅读文档的放置规则，把“运行规范”和“用户阅读材料”彻底分开，避免 `docs/` 继续混放。
- 为文档放置和说明文件治理增加自动审核模块，让这类问题进入 harness，而不是依赖人工记忆。
- 继续优化 `config-ui` 的布局、面板、说明和交互，把当前页面修到更稳定、更统一的状态。

## 背景与定位
- 当前 `exec_plan` 的机器模板已经迁到 `config/templates/exec_plan_template.md`，`docs/exec_plans/TEMPLATE.md` 只剩导航作用，继续保留的价值已经很低。
- `docs/workflow_specs/` 中仍混有明显偏“用户阅读”的文件，用户要求检查并迁移到 `user_guides/`。
- `config-ui` 经过多轮重构后，主要问题集中在面板布局、间距不一致、局部滚动、说明位置和人工中转页面组织方式。
- 本轮不只是改页面，还要同步增加文档放置监管与 UI 审查逻辑，保证后续能自动发现回退。

## 计划中的工作
- 先做文档治理和文档审核模块，再做 UI 布局细化。
- UI 调整时同步更新自动审核规则和测试，不接受“页面修了但 harness 不知道”的状态。
- 完成后做一次完整 gate 校验，再归档计划。

## 具体步骤
1. 审核 `docs/` 当前文件职责，把明显偏用户阅读的文件迁到 `docs/user_guides/`，并处理 `docs/exec_plans/TEMPLATE.md`。
2. 新增文档放置审核模块，定义哪些文件必须在 `workflow_specs/`，哪些必须在 `user_guides/`，并把检查接入 `harness-check`。
3. 修改总览页结构，移除交互日志卡片，改为运行状态检查卡片，并统一 overview 各面板间距。
4. 修复周报期刊列表卡片的高度与滚动布局，让内容完整填充卡片。
5. 调整人工中转页：最近活动只保留 3 条，请求生成和响应解读分两行，请求按钮右侧直接给出 `prompt.md` 操作入口。
6. 调整设置页布局，让“分析后端与服务”和“路径与输出”分两行展示。
7. 更新 UI 审查模块和测试，最后跑完整 gate 并归档。

## 发现与意外
- `harness-check` 之前已经接入 `config_ui_review`，但 UI 真实结构变更后，审查模块和测试没有同步更新，导致 gate 失真。
- `docs/` 的文件放置问题如果只靠目录约定很容易回退，必须做成显式审核模块。
- 这轮 UI 没有新增单模块超预算，但总包有效代码行数超出旧预算 93 行，需要按“新增治理模块”而不是“任意膨胀”来调整总量预算。

## 决策记录
- `ExecPlan` 的机器模板 source of truth 固定在 `config/templates/exec_plan_template.md`；`docs/exec_plans/TEMPLATE.md` 删除，不再保留导航页。
- 说明文件放置监管以 `src/sciencemonitor/docs_review.py` 实现，并纳入 `harness-check`，而不是只写在文档约定里。
- 总览页不再保留“交互日志”，统一替换为“运行状态检查”，聚焦 `doctor` 和 `maintenance-check` 的结果。
- `config_ui_review` 继续作为 UI 审核 gate，但必须跟着真实页面结构同步维护。
- `package_total_max_lines` 从 `13150` 调整到 `13350`，只承认这轮治理模块带来的必要总体体量，不放宽单模块预算。
