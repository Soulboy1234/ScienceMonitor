# 2026-04-10 重定向占位总结修复计划

## 目的 / 大图景

- 修复 `Redirecting` 这类跳转页标题污染单篇总结的问题。
- 防止仅有元数据或跳转占位信息的条目被错误打上具体学科标签。
- 保证后续同类问题不会继续通过缓存和旧输出重复扩散。

## 背景与定位

- 用户发现已有总结文件中出现 `Mishra 2026 - ASR - 重定向页面，无法判定具体研究内容` 这类异常卡片。
- 这类卡片一方面把网页跳转标题写进了总结，另一方面还保留了 `#电离层`、`#磁暴` 等具体主题标签，语义不一致。
- 该问题属于单篇总结抓取、分析缓存和标签后处理的交叉缺陷。

## 进度

- [x] 回查异常总结文件和对应 DOI、作者、缓存记录
- [x] 确认数据库中的真实题名与异常总结不一致
- [x] 修复跳转页标题覆盖真实题名的问题
- [x] 新增元数据级来源标签与说明
- [x] 收紧元数据级条目的标签逻辑
- [x] 让文章分析缓存 key 纳入标题，避免旧坏缓存复用
- [x] 补测试并通过 harness / entropy

## 发现与意外

- 数据库中的 `10.1016/j.asr.2026.01.082` 真实题名是正常的，不是 `Redirecting`。
- `Redirecting` 不是数据库存进去的，而是单篇总结链路在 DOI 页面抓取时，把跳转页 `<title>` 覆盖成了有效标题。
- 旧缓存 key 不包含题名，导致一旦某 DOI 生成过坏结果，后续即使元数据变正确，也可能继续复用旧坏缓存。

## 决策记录

- 不再信任网页页面标题中的 `Redirecting` / `Loading` / `Just a moment` 等占位值。
- 新增 `信息来源/仅元数据` 状态标签，用于“没有有效摘要或全文”的记录。
- 元数据级记录不再保留具体学科主题标签，避免制造“看起来像真的”误导卡片。
- 这次同步微调维护预算，避免对已确认必要的修复报假阳性。

## 计划中的工作

- 修复标题选择逻辑
- 修复元数据级标签逻辑
- 修复缓存复用逻辑
- 补充回归测试
- 重新跑 harness 和 entropy

## 具体步骤

1. 检查异常总结文件、LLM 缓存和数据库记录，定位污染点。
2. 在 `article_fetch.py` 中跳过跳转页标题。
3. 在 `article_summary_text.py` / `article_summaries.py` 中增加元数据级来源规则。
4. 在 `llm.py` 中把题名加入文章缓存 key。
5. 补测试，验证：
   - `Redirecting` 不再覆盖 Crossref / 数据库题名
   - 元数据级总结只保留 `信息来源/仅元数据`
   - 文章缓存 key 会随题名变化
6. 跑 `entropy-check` 和 `harness-check`。

## 结果与复盘

- 修复后，跳转页标题不再覆盖真实题名。
- 仅有元数据的记录会被明确标成 `信息来源/仅元数据`，不再误打 `#电离层` 等具体主题标签。
- 文章分析缓存已随题名变化而变化，旧坏缓存不会在题名修正后继续复用。
- `entropy-check`、`harness-check` 和定向测试均通过。
