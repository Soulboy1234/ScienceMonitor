# 计划：2026-04-09_UI导航栏状态面板重构

## 目的 / 大图景
- 在不干扰当前周报任务运行的前提下，重构左侧导航栏下方的信息显示区域。
- 将“静态环境信息”和“动态任务状态”分离，避免无关信息长期占据导航栏。
- 把这次导航栏状态逻辑继续纳入现有 UI harness 审查范围，避免后续回退。

## 背景与定位
- 当前导航栏下方混合显示 provider、周报模式、人工中转统计、面板地址、输出目录，层次不清。
- 用户希望保留的静态信息只有：当前 LLM/provider、面板地址、输出目录。
- 用户希望在其上方新增一个运行状态面板，专门显示：当前运行中的任务，以及与该任务相关的动态信息。
- 人工中转状态只应在人工中转任务相关时显示；没有 pending 时不展示。
- `周报模式 / 手动生成已启用` 不再显示。

## 工作范围
- `src/sciencemonitor/config_ui_page_sections.py`

## 非目标
- 不重启当前正在提供服务的 UI 进程。
- 不中断正在运行的周报任务。
- 不改变右侧主内容区布局。

## 进度

- [x] 步骤 2：实现导航栏运行状态面板与静态信息面板拆分
- [x] 步骤 3：调整人工中转状态显示条件
- [x] 步骤 4：补测试与 UI 审查规则
- [x] 步骤 5：校验并记录“待任务结束后重启服务”

## 计划中的工作
- 先改侧栏渲染逻辑，拆出“运行状态”面板。
- 再让动态任务面板根据 `active_task` 和人工中转 pending 状态按条件显示。
- 最后更新测试与 harness 审查规则。

## 具体步骤
1. 将导航栏下方信息拆成两个卡片：运行状态卡片、静态信息卡片。
2. 静态信息卡片只保留：当前 LLM/provider、面板地址、输出目录。
3. 动态状态卡片优先显示运行中的任务；若无运行任务但存在人工中转 pending，则显示人工中转待处理数；否则显示“当前无运行任务”。
4. 删除“周报模式 / 手动生成已启用”展示。
5. 补测试，确保导航栏不会始终显示人工中转状态，且结构符合新布局。

## 发现与意外
- 当前 UI 服务正在承载用户手动触发的周报任务，因此这轮不能直接重启服务；否则会干扰用户正在进行的试验。
- 这轮改动可以先完成代码、测试和 harness 校验，再等任务结束后切换到新服务进程。

## 决策记录
- 导航栏信息分为两类：动态运行状态放独立卡片，静态环境信息放底部卡片。
- 人工中转状态不再长期显示；仅在没有运行中任务且存在 pending 请求时，才在运行状态卡片中展示。
- 不在当前周报任务运行过程中重启 UI 服务，避免干扰试验。

## 结果与复盘
- 左侧导航栏下方已改为“运行状态卡片 + 静态信息卡片”。
- 静态信息只保留：当前 provider、面板地址、输出目录。
- “周报模式 / 手动生成已启用”已从导航栏移除。
- 在周报任务结束后已重启 UI 服务，新布局现已对浏览器生效。
