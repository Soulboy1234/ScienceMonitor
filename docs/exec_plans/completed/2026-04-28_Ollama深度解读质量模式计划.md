# 计划：2026-04-28_Ollama深度解读质量模式

## 目的 / 大图景
- 优化 `ollama_api` 深度解读质量，让本地模型更接近 Codex 深度解读的结构完整度和判断密度。
- 保持单篇文章总结的摘要优先策略：摘要级资料只做摘要级总结，不强制获取全文。
- 把“文章总结”和“深度解读”的证据边界写进代码和 harness，避免后续混淆。

## 背景与定位
- 当前同一篇深度解读中，Codex 输出明显比 Ollama 输出更丰富。
- 实测对比显示 Codex 深度解读使用更高推理预算，Ollama 当前更像结构化草稿。
- 代码中 Ollama system prompt 仍写着“只根据标题、摘要和元数据”，这会压低深度解读对全文的使用。

## 非目标
- 不把单篇文章总结改成强制全文分析。
- 不把 Ollama 伪装成 Codex 级别模型；本轮目标是拉近质量、增加稳定性和可控性。
- 不删除或重写现有深度解读输出文件。

## 计划中的工作
- 先修正 Ollama provider 的任务类型感知提示词。
- 再为深度解读增加 Ollama 专用证据分析阶段，把证据链注入最终生成 prompt。
- 同步增加 `num_ctx`、`num_predict` 等可配置项，避免本地模型隐性短输出。
- 最后用测试确认文章总结仍不会强制全文，深度解读会走全文级提示和证据预分析。

## 具体步骤

2. 为 deep_read 增加全文级 system prompt 和默认输出长度参数。
3. 增加 deep_read evidence schema/prompt，并仅在 `provider == ollama_api` 时使用。
4. 更新 UI 保存/展示 Ollama 参数。
5. 更新配置说明和测试。
6. 运行 targeted tests、全量测试和 harness-check。

## 发现与意外
- Ollama 底层 system prompt 原先对所有任务都写成“标题、摘要和元数据”，深度解读实际拿到全文时也会被提示词压成摘要级分析。
- 同一篇深度解读中，Ollama token 量显著低于 Codex，说明本地模型需要显式增加输出预算和证据组织步骤。

## 决策记录
- 单篇总结继续按来源文本工作；如果来源只有摘要，就只做摘要级总结，不因 Ollama 质量模式强制读全文。
- Ollama 深度解读新增两阶段质量模式：第一阶段做全文证据预分析，第二阶段把证据提纲和全文一起送入最终深度解读。
- `num_ctx`、`num_predict` 暴露为配置项，但不直接修改摘要总结证据边界。

## 结果与复盘
- Ollama 自动分析现在按任务类型使用不同 system prompt：单篇总结保留“来源文本可能只是摘要”的边界，深度解读明确使用全文或全文级长文本。
- Ollama 深度解读增加质量模式，默认开启；缓存签名包含 `num_ctx`、`num_predict` 和质量模式状态，避免新旧配置混用缓存。
- 设置页已暴露 `num_ctx`、`num_predict` 和“深度解读质量模式”，并写入 `config/analysis.json` / `PROJECT_CONFIG.md`。
- harness 初次失败来自既有输出库的 5 个标签审核问题；已用项目标签审核器重写标签行后通过。
