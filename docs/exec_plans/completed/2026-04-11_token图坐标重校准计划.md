# 计划：2026-04-11_token图坐标重校准

## 目的 / 大图景
- 修复总览页 token 图仍然存在的坐标错位问题，确保柱高、y 轴刻度、x 轴标签三者一致。
- 把这类“服务未重载”和“图表数值正确但视觉坐标错位”问题补进 harness。

## 背景与定位
- 用户反馈 2026-04-09 的 `463,894` 柱体仍未超过 `400,000` 虚线，说明当前可见页面不是正确坐标，或坐标系本身仍有错位。
- 用户反馈 x 轴标签不均匀，且末尾标签语义和柱体位置混乱，说明当前标签渲染策略和列中心对齐仍不可靠。
- 当前运行中的 UI 服务实际还在输出旧版 token 图 HTML，需要把“代码已改、服务未重载”纳入排查流程。

## 工作范围
- `src/sciencemonitor/config_ui_page_sections.py`
- `src/sciencemonitor/ui_assets/config_ui.css`
- `src/sciencemonitor/config_ui_visual_review.py`
- `tests/test_config_ui.py`

## 非目标
- 本轮不修改 token 统计来源。
- 本轮不修改除总览页 token 图之外的其他页面交互逻辑。

## 进度
- [x] 步骤 1：确认当前 UI 服务仍在提供旧版 token 图 HTML。
- [x] 步骤 2：修复 token 图坐标与标签渲染。
- [x] 步骤 3：补测试、视觉检查，重启面板并复核实际服务输出。

## 计划中的工作
- 先核对在线服务端返回的 token 图 HTML，确认是否仍在使用旧版渲染。
- 再统一 token 图的 y 轴刻度、网格线和底部基线。
- 再把 x 轴标签改成不贴右边界的均匀采样，并按列中心对齐。
- 最后重启面板，直接检查在线 HTML、截图和 harness 结果。

## 具体步骤
1. 对比源码与在线 HTML，确认旧服务仍在输出旧版 `left:%` 标签。
2. 修复 y 轴刻度、网格线、x 轴基线的统一定位。
3. 修复 x 轴标签的均匀分布与列中心对齐，并给图表左右留出一致边距。
4. 更新测试和视觉检查规则。
5. 重启 `config-ui`，核对实际页面、截图与 harness。

## 发现与意外
- 当前源码里的 token 图渲染已经切到 `grid-column` 思路，但在线服务仍返回旧版 `left:%` 标签 HTML，说明问题不只在代码，还在运行态刷新链路。
- 首个 x 轴标签在严格中心对齐时会轻微越出左边界，必须通过图表内边距解决，不能靠放宽 harness 阈值掩盖。

## 决策记录
- x 轴标签改成“均匀列索引 + 列中心对齐”，不再强行把最后一个非零日期塞成末尾标签。
- y 轴 0 刻度与基线使用同一条坐标线，不再让 border 和刻度各走一套定位。
- harness 新增“0 刻度是否与底部基线重合”的检查，避免以后再次出现数值对但坐标错位的假通过。

## 结果与复盘
- 在线服务现已输出新版 token 图 HTML：
  - y 轴刻度与网格线都使用 `0 / 100,000 / ... / 500,000` 的同一组坐标。
  - `2026-04-09` 柱高为 `93%`，`2026-04-10` 柱高为 `88%`。
  - x 轴标签改为 `3/13, 3/19, 3/25, 3/31, 4/6` 这组均匀采样，不再贴右边界。
- 定向视觉检查和全量 harness 均恢复通过。
