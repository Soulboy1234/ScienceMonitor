# 计划：2026-04-11_token图纵轴自适应修复

## 目的 / 大图景
- 把 token 图纵轴改成可自适应的整数刻度。
- 保证底部永远是 0，顶部由当前 30 天窗口最大值向上取整决定，总刻度数控制在 5 到 8 个之间。

## 背景与定位
- 当前纵轴步长主要依赖粗略的 nice number 规则，虽然能工作，但还没有显式满足“总刻度数 5-8 个”“允许以 10000 为粒度调整步长”这两个约束。
- 用户已经明确给出刻度策略，需要把它落实成稳定的计算逻辑和 harness 约束。

## 工作范围
- `src/sciencemonitor/config_ui_page_sections.py`
- `src/sciencemonitor/config_ui_visual_review.py`
- `tests/test_config_ui.py`

## 非目标
- 本轮不改 token 数据来源。
- 本轮不改 x 轴槽位策略和 bar 高度逻辑。

## 进度
- [x] 步骤 1：重写纵轴刻度生成算法。
- [x] 步骤 2：补测试和视觉审查规则。
- [x] 步骤 3：重启面板并验证在线页面。

## 计划中的工作
- 先把纵轴步长计算改成“搜索候选整数步长”。
- 再让步长优先使用 10000 粒度的大整数，并控制总刻度数。
- 最后补测试、重启 UI、核对在线 HTML。

## 具体步骤
1. 重写 `_build_token_tick_values()` 的步长选择。
2. 补单测，覆盖顶部取整、刻度数范围和步长粒度。
3. 补视觉审查，检查 y 轴刻度数是否在 5-8 之间。
4. 重启 `config-ui` 并核对在线页面。

## 发现与意外
- 初次在线核对时，用 `rg token-y-tick` 抓到的是 CSS 片段，不是图表主体，容易误判为页面仍在使用旧刻度；需要直接抓 `token-usage-block` 主体 HTML 才能确认实际渲染结果。

## 决策记录
- 顶部优先选择“最小可用上界”，而不是固定偏好 100000 这种单一步长。
- 步长搜索采用整数候选步长，并优先选择 headroom 最小、刻度数更接近目标值的方案。
- 大于等于 `100000` 的量级优先使用 `10000` 为粒度，满足用户对整数刻度的要求。

## 结果与复盘
- 当前在线 y 轴已变为自适应整数刻度：`480,000 / 400,000 / 320,000 / 240,000 / 160,000 / 80,000 / 0`。
- 总刻度数为 `7`，落在 5 到 8 个之间。
- 这套规则现在会跟随 30 天窗口最大值自动变化，不会固定死在 `100000` 步长上。
