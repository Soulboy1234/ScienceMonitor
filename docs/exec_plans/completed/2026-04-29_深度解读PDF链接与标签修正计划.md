# 计划：2026-04-29_深度解读PDF链接与标签修正

## 目的 / 大图景
- 修复深度解读顶部 PDF 链接 target，显示文字仍为 `PDF`。
- 优化深度解读 tag 生成与后处理，使其学习单篇总结的“闭集优先、具体优先、父子压制、保守不脑补”风格。

## 背景与定位
- 当前深度解读生产输出会把 PDF 资源渲染成 Obsidian wikilink，`obsidian_target()` 默认去掉 `.pdf` 后缀，导致 PDF target 不准确。
- Ollama 深读已经能生成较完整正文，但 tag 中出现 `对象/物理机制/*`、`对象/能量转换/*` 这类观点摘抄式虚对象。
- Codex 和 Ollama 深读应共享同一套 tag 后处理规则，但本轮不改 Codex 深读正文质量逻辑。

## 发现与意外
- Akasofu PDF 抽取文本中 `solar wind–magnetosphere`、`currentlines` 等 OCR/排版形态需要兼容，否则实体 tag 推断不足。
- `CHAMP` 会被 `Chapman` 参考文献/OCR 误带出；已限制为 deep-read context 下必须有独立 `CHAMP` 证据才保留。
- Harness 的 tag output review 会因为单篇总结 tag 纯顺序差异失败；已调整为语义集合相同时不报 issue，从而不重写单篇总结输出。

## 决策记录
- 生产深读 PDF 链接使用相对 Markdown 链接，例如 `[PDF](<../deep_reads_pdf/example.pdf>)`。
- 单篇总结只是 tag 风格参考，本轮不重写单篇总结输出。
- 纯 tag 顺序差异不再作为输出审计失败条件；实际 tag 集合变化仍会失败。
