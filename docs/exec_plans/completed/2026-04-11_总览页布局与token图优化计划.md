# 计划：2026-04-11_总览页布局与token图优化

## 目的 / 大图景
- 优化总览页的信息密度和视觉层次，让“运行统计”“运行状态检查”“LLM 状态”更紧凑、更稳定。
- 把 token 图从简单柱形展示升级为带坐标轴、网格线和悬浮提示的统计图，并纳入视觉检查。

## 背景与定位
- 当前总览页的四个运行统计卡片在窄窗口下可能换行，不符合固定总览结构要求。
- “运行状态检查”占用空间偏大，状态信息和操作按钮的布局不够紧凑。
- Token 图虽然已经有柱状图，但还缺少更明确的坐标系和交互提示，也没有被充分纳入 visual review。

## 工作范围
- `src/sciencemonitor/config_ui_page_sections.py`
- `src/sciencemonitor/ui_assets/config_ui.css`
- `src/sciencemonitor/ui_assets/config_ui.js`

- `src/sciencemonitor/config_ui_review.py`

- `tests/test_config_ui_visual_review.py`

## 非目标
- 本轮不重做其他页面布局。
- 本轮不引入新的图表库，保持纯 HTML/CSS/JS。

## 进度
- [x] 步骤 1：确认总览页当前结构和视觉约束。
- [x] 步骤 2：调整总览页布局与检查卡片结构。
- [x] 步骤 3：增强 token 图坐标、网格和悬浮提示。
- [x] 步骤 4：补测试和视觉检查。

## 计划中的工作
- 先改总览页 DOM 结构，再改 CSS，最后补前端悬浮交互。
- 然后把关键视觉特征纳入 Playwright visual review，避免再次出现“视觉检查通过但图不对”。

## 具体步骤
1. 固定运行统计四卡片一排。
2. 压缩“运行状态检查”面板文本布局，并整理按钮位置。
3. 调整总览页卡片顺序，让 LLM 状态上移。
4. 为 token 图补纵坐标、横坐标、虚线网格和 hover tooltip。
5. 运行测试与 harness 验证。

## 发现与意外
- 总览页原有 visual review 只验证 token 图存在和大致高度，不会检查运行统计是否同排，也不会检查 LLM 状态和运行状态检查的相对顺序。
- `py_compile` 不能用来检查 `.js` 文件；这次 JS 交互正确性主要依赖浏览器实际 visual review 和 pytest 中的静态片段检查。

## 决策记录
- 运行统计保持固定四列，不再因窄窗口自动折成两列。
- “运行状态检查”改成紧凑行式表达，所有通过项统一显示“正常”，只有异常时才展开具体问题。
- LLM 状态上移到运行状态检查之前。
- token 图继续保持纯原生 HTML/CSS/JS，新增坐标轴、虚线网格和 hover tooltip，不引入第三方图表库。

## 结果与复盘
- 总览页的四个运行统计卡片现在固定同排。
- 运行状态检查已压缩成两行高密度布局，按钮移动到右侧空白区。
- token 图新增了纵轴、横轴、浅色虚线网格和鼠标悬浮提示，视觉检查已覆盖这些关键结构。
- 这轮约束已经写进 review / visual review，后续再改总览页时更容易及时发现回退。
