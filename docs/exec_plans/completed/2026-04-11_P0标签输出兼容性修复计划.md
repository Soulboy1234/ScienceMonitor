# 计划：2026-04-11_P0标签输出兼容性修复

## 目的 / 大图景
- 修复当前输出到 Obsidian 的标签在包含 `+`、小数点等字符时被错误拆分的问题。
- 保证单篇总结、周报、深度解读三条链路输出一致，并且从 Markdown 回读时仍能恢复为程序内部的 canonical tag。

## 背景与定位
- `Todo.md` 的首个 `P0` 问题已经明确指出：如 `He+波段` 这类标签在 Obsidian 中会断裂。
- 当前内部标签规范允许保留 `+`、`.`、`&` 等字符，问题不在标签归一化层，而在 Markdown 输出层直接拼接 `#tag`。
- 周报和深读存在独立的手写 `#` 拼接逻辑，属于链路分叉风险。

## 工作范围
- `src/sciencemonitor/article_summary_markdown.py`
- `src/sciencemonitor/reporting.py`
- `src/sciencemonitor/deep_reads.py`
- `tests/test_article_summaries.py`
- `tests/test_reporting.py`
- `tests/test_deep_reads.py`
- `docs/exec_plans/Todo.md`

## 非目标
- 本轮不收缩或重命名内部 canonical tag。
- 本轮不调整标签推断、候选标签吸收或焦点标签配置。
- 本轮不处理周报正文内容和标准校准。

## 进度
- [x] 步骤 1：定位问题在 Obsidian 输出层，而不是内部标签规范层。
- [x] 步骤 2：实现安全输出、回读解码，并统一周报/深读复用。
- [x] 步骤 3：完成 gate 验证、更新 Todo，并归档计划。

## 计划中的工作
- 先在单篇总结的标签输出模块中引入 Obsidian 安全编码与反向解码。
- 再让周报和深读复用同一套标签输出函数，消除手写分叉。
- 然后补针对 `+`、`.`、`&` 的回归测试。
- 最后跑测试和 harness gate，并同步清理 `Todo.md`。

## 具体步骤
1. 修改 `article_summary_markdown.py`，增加安全编码/解码函数，并更新 `format_tag`、`build_tag_line`、`extract_summary_tags`。
2. 修改 `reporting.py` 和 `deep_reads.py`，删除手写 `#` 拼接，统一复用 `build_tag_line`。
3. 修改测试，覆盖特殊符号标签的输出和回读，以及周报/深读渲染结果。
4. 运行定向测试和 `harness-check`，确认没有引入新漂移。
5. 更新 `Todo.md`，并把计划移入 `completed/`。

## 发现与意外
- 初次 `harness-check` 失败不是代码问题，而是 active plan 没有完全遵循固定模板。
- `config_ui`、golden eval、docs review 在这轮代码变更下都保持稳定，没有额外回归。

## 决策记录
- 保留内部 canonical tag 原样，不在内部层面删除 `+`、`.` 等信息。
- 仅在 Markdown/Obsidian 输出层做安全编码，并在读回时解码，避免破坏既有规则和候选标签体系。
- 使用全角字符作为输出编码，保持人眼可读性，同时避免 Obsidian 把标签截断。

## 结果与复盘
- 当前采用的输出编码规则为：`+ -> ＋`、`. -> ．`、`& -> ＆`，仅作用于 Markdown/Obsidian 输出层。
- 单篇总结、周报、深度解读现在统一复用 `build_tag_line()`，避免三条链路各自漂移。
- Markdown 回读现在会自动把安全编码解回 canonical tag，因此不会影响深读挂接、缓存复用和后续标签判断。
- 这轮没有改内部标签体系，也没有改候选标签机制；风险面集中在展示层，已经被定向测试和 harness gate 覆盖。
