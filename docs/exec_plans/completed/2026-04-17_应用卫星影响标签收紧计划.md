# 计划：2026-04-17_应用卫星影响标签收紧计划

## 目的 / 大图景
- 收紧 `应用/卫星影响` 的自动判定，避免把“仅提到卫星、轨道、阻力”等背景词的文章误标成卫星应用影响论文。
- 保持 formal 标签体系稳定，让该标签只在论文主体明确讨论空间环境/空间天气如何影响卫星运行、轨道、阻力环境、任务安全或工程运行时出现。

## 背景与定位
- 当前 `应用/卫星影响` 打得过频，主要原因是单篇总结标签归一化规则过宽。
- 用户已明确新的边界：只有正文主要讨论内容是“空间环境如何影响卫星运行”时才打；把卫星轨道变化当成一个例子，不足以触发。

## 工作范围
- `src/sciencemonitor/article_summary_text.py`
- `tests/test_article_summaries.py`
- 必要时补充相关规则文档

## 非目标
- 不在本轮重审全部 `auto` 输出。
- 不调整 `应用/*` 其他标签。
- 不修改深度解读正文内容或周报内容。

- [x] 步骤 2：补充回归测试，覆盖“仅背景提到”与“主体明确讨论”两类边界
- [x] 步骤 3：跑验证并视需要更新文档

## 计划中的工作
- 先读当前标签归一化实现，确认实际触发词和调用路径。
- 再把规则改成必须同时满足“卫星/轨道/阻力对象”与“影响/响应/风险/预报/运行”语义。
- 用测试锁住“只提到卫星”不触发、“主要讨论卫星影响”才触发。
- 最后跑对应测试与 harness。

## 具体步骤
1. 查看 `article_summary_text.py` 中与 `应用/卫星影响` 相关的自动补标签逻辑。
2. 增加更严格的语义门槛，避免只因 `satellite drag` 等词出现就直接触发。
3. 补测试覆盖英文与中文边界样例。
4. 执行局部测试和必要的总体验证。

## 发现与意外
- 过度触发的核心不只在规则补标签层，也在标签审核层：即使 LLM 直接产出 `卫星影响`，原先也会被无条件保留并归一化为正式标签。
- 当前项目里最合适的收口点是 `tag_review.py`，因为这里既能约束 LLM 输出，也能约束规则补标签结果。

## 决策记录
- `应用/卫星影响` 现在必须同时满足三类证据：卫星/轨道对象词、空间环境/空间天气背景词、以及影响/风险/运行/任务/预报等语义词。
- 当没有任何正文上下文时，不强行删手工标签；只有拿到标题/正文/补充文本上下文时，才执行证据约束。

## 结果与复盘
- 已收紧 `应用/卫星影响` 自动触发逻辑，并把同样的收紧规则接到标签审核层。
- 新增了两类回归测试：背景顺带提到卫星阻力时不触发；主体明确讨论空间环境对卫星运行/轨道影响时触发。
- 当前只改了未来生成与审核逻辑；如果要把现有 `auto` 输出里已误打的此标签批量重审，需要另开一轮计划。
