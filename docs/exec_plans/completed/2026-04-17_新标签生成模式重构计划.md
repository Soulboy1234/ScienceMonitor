# 计划：2026-04-17_新标签生成模式重构计划

## 目的 / 大图景
- 重构文章总结和深度解读的新标签生成模式，优先吸收进正式标签，严格限制新增 pending 标签。
- 目标不是“尽量多打标签”，而是“用尽量少、尽量稳的标签概括文章真实意图”，同时控制项目标签熵。
- 最终要求是在当前这批约 32 篇 `auto` 输出上，pending 规模显著收敛，不再出现“30 多篇文章产出 100+ 个一性一议的新标签”这种失控状态。

## 背景与定位
- 当前 `auto/article_summaries` 共 32 个文件，平均每篇约 `8.03` 个标签。
- 当前 pending 仍有 `143` 个真实标签，几乎全部都是 `1次`，明显超过合理规模。
- 现有问题不是简单字符串未对齐，而是标签粒度失控：
  - formal 误打：例如只因出现背景词就生成 `对象/热层/密度`
  - pending 过宽：地区、时间、组织、人群、参数细项、一次性观测细节都进入了 pending
  - 终态缺少“语义压缩”：生成后的标签没有被进一步压缩为 formal 风格下更稳定的少量概念
- 额外发现：
  - 当前 pending 与 formal 几乎没有简单的 suffix/leaf 重复，说明核心问题不是字符串差一点，而是语义层级过细、表达方式太贴正文细节。

## 工作范围
- `src/sciencemonitor/article_summary_text.py`
- `src/sciencemonitor/tag_review.py`
- `src/sciencemonitor/tag_governance.py`
- 如有必要，少量调整 `src/sciencemonitor/tags.py`
- 相关测试
- 现有 `auto/article_summaries` 与 `config/tag/pending_tags.md`

## 非目标
- 不改 `manual` 输出
- 不直接扩 formal 标签树
- 不先优化周报正文内容
- 不追求“一篇文章所有细节都有对应标签”

## 进度
- [x] 步骤 1：量化当前 pending 规模、标签粒度和重复模式
- [x] 步骤 2：实现“候选标签 -> formal 吸收 -> pending 准入 -> 终态压缩”的新链路
- [x] 步骤 3：对现有 auto 输出迭代重审，直到 pending 规模明显收敛
- [x] 步骤 4：更新 golden / harness 基线并收尾

## 计划中的工作
- 先把新标签生成模式从“开放式收集”改成“严格审稿制”。
- 再把 pending 准入从“合法字符串即可”改成“必须有审阅价值”。
- 然后给每篇文章增加终态压缩，限制单篇新增 pending 的数量和粒度。
- 最后反复重审现有 `auto` 输出，边看边补规则，直到 pending 收敛到目标区间。

## 具体步骤
1. 建立新的生成链路：
   - 候选标签生成：允许从标题、摘要、正文总结、补充说明中先提一批候选。
   - formal 吸收：凡是与正式标签语义重合、可压到正式父类、或只是正文细节换说法的，优先吸收到 formal。
   - pending 准入：只有“真实新概念 / 新仪器 / 新方法 / 新应用类型 / 新稳定研究对象”才允许进入 pending。
   - 终态压缩：对每篇文章限制新增 pending 数量，并移除正文细碎复述型标签。
2. 收紧 pending 规则：
   - 默认拒绝地区、时间、组织、人群、观测站、多点观测、参数细项、指标细项、载荷、介质、驱动细项、一次性事件日期等标签。
   - 默认拒绝“只是把正文名词短语改成层级字符串”的候选。
   - 对科学对象类新标签，要求更强的概念稳定性，避免把结果特征或局地表述直接入 pending。
3. 增加单篇约束：
   - 每篇文章新增 pending 标签设上限。
   - 同一篇文章中，如果一个新标签已经可由 formal 标签概括，就不再保留该 pending。
   - 单篇标签整体也要压缩，避免把摘要里的每个名词都映射成标签。
4. 迭代目标：
   - 当前这批 `32` 篇 `auto` 输出，pending 总量从 `143` 降到 `<= 60`
   - 平均每篇标签数从约 `8.03` 压到 `4-6` 的稳定区间
   - `tag_output_review` 维持 `0 issue`
   - `harness-check` 全绿

## 发现与意外
- `pending` 当前高频项几乎没有，全部都是 `1次`，说明系统还处在“遇到什么都建新标签”的状态。
- 很多 pending 项本质上不是“新研究方向”，而是文章里的局部对象或说明词，例如台站、时段、参数、地区、观测方式。
- 现有 formal 树已经足够大，新增标签的主要问题不是 formal 不够，而是生成器没有主动往 formal 上收敛。

## 决策记录
- 不再把“开放词表”当默认策略；开放词表只对高价值新概念保留。
- pending 不是历史日志，而是人工审阅池；进入 pending 的标准必须更高。
- 单篇文章标签的目标是“概括主旨”，不是“记录全文所有实体”。

## 结果与复盘
- 已把“开放式收集 pending”改成“formal 优先吸收 + 低价值拒绝 + 单篇限额 + 终态压缩”的新链路。
- `auto/article_summaries` 维持 `32` 个文件，平均标签数从约 `8.03` 降到 `5.53`。
- `pending` 从 `143` 个真实残留标签收敛到 `24` 个，明显低于预设上限 `60`。
- `run_tag_output_review()` 结果为 `0 issue`，说明现有 `auto` 输出与审核逻辑已对齐。
- `harness-check` 全绿，`golden_eval` 维持通过，说明这轮收紧没有破坏展示层和既有基线。
- 这轮有效的方法不是继续堆关键词，而是：
  - 把与 formal 语义重合的项直接重写到 formal；
  - 把站点、局地参数、一次性观测细节、重复方法词等低价值候选挡在 pending 之外；
  - 把同一篇文章里多个“同类细碎新标签”压缩为极少数真正需要人工审阅的项。
- 剩余 `24` 个 pending 大多是稳定但 formal 里尚未收录的仪器、模型、索引或确实新的研究对象，已经脱离“正文名词直接入库”的失控状态。
