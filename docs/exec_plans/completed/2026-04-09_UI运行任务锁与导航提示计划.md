# 计划：2026-04-09_UI运行任务锁与导航提示

## 目的 / 大图景
- 在 `config-ui` 中把正在运行的后台任务显式展示到左侧导航栏，避免用户切换页面后丢失运行上下文。
- 在不阻止页面导航的前提下，限制新的任务启动，避免多个重任务并发破坏本地单机工作流。
- 把这条规则纳入现有 harness，保证 UI 状态提示和任务互斥不会再次回退。

## 背景与定位
- 当前周报后台任务启动后，用户切换到其他功能页时看不到全局提示。
- 用户希望：任务继续运行，UI 允许继续浏览其他页面，但要清楚提示“当前有任务正在运行”，并阻止其他任务启动。
- 这涉及运行态状态文件、导航栏渲染、前端轮询和后端动作守卫。

## 计划中的工作
- 先把 `report_job` 提炼成统一的“active task summary”。
- 再在会启动任务的 POST 动作上加互斥判断，允许查看页面，不允许并发启动新任务。
- 最后把状态展示到导航栏，并由前端轮询刷新。

## 具体步骤
1. 在运行态模块中增加读取当前活动任务摘要的辅助函数。
2. 在 UI POST 处理链路上，对 `run-report`、`run-deep-read`、`manual-llm-*` 这类动作增加互斥守卫。
3. 在左侧导航栏底部显示当前运行任务和步骤信息。
4. 让前端轮询 `/ui-status` 时同步刷新导航栏的任务提示。
5. 补充测试，验证：
   - 有运行中周报时不能启动其他任务
   - 导航栏能显示运行中任务
   - 页面切换不受影响

## 发现与意外
- 问题不只是“周报状态卡看不见”，而是提交周报后页面被重定向回总览，导致用户错过了运行状态面板。
- 仅有后端任务状态还不够，导航栏也必须给出全局提示；否则用户切走页面后会误以为任务停止了。

## 决策记录
- 继续沿用现有 `report_job` 作为后台运行状态源，不引入第二套任务状态模型。
- 任务互斥先按“当前有运行中周报时，阻止其他启动类动作”处理；页面导航、查看结果和保存配置不受影响。
- 前端除了轮询周报状态卡，也同步轮询左侧导航栏的“运行任务”提示，并在运行期间禁用启动类按钮。

## 结果与复盘
- 左侧导航栏现在会显示当前运行任务及步骤，例如“周报任务 · 抓取与筛选文章”。
- 当周报任务运行中时，新的周报、深度解读、人工中转启动动作都会被后端拒绝，前端按钮也会禁用。
- 页面导航不受影响，用户可以切换到其他页面查看内容，周报任务继续在后台运行。
- 这次把“长任务全局可见 + 任务互斥”补进了 UI harness，避免再次出现“任务在跑但用户无感知”的问题。
