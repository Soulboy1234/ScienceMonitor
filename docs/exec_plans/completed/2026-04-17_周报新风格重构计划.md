# 计划：2026-04-17_周报新风格重构

## 目的 / 大图景
- 按 `log/report_update/report_new_design.md` 的新设计，重写周报的正式展示结构和内容生成逻辑。
- 让周报从“松散罗列”变成“信息表格 + 概览判断 + 文章推荐 + 主题推荐 + 期刊汇总”的稳定结构。
- 在正式重新跑真实周报前，先把模板、程序、审核和 harness 基线写稳，后续再用 UI 手动生成真实周报做校准。

## 背景与定位
- 现有周报结构仍是旧版：概览 / 分类 / 建议 / 重点论文 / 主题 / 期刊 / 附注。
- 用户已经清空了除 `2026-04-06 周报.md` 之外的大部分 `auto` 文件，因此本轮不做真实周报内容修复，只做程序和治理重构。
- 这轮的核心是“重写周报计算逻辑与审查规则”，不是恢复历史输出。

## 计划中的工作
- 先把新版周报章节和占位符定死，避免边写逻辑边漂移。
- 再根据 formal 标签风格重建“方向统计 / 文章推荐 / 主题推荐 / 期刊汇总”的数据组织。
- 随后把周报审核规则从“轻量空行修复”提升到“结构与格式契约检查”。
- 最后更新测试和 golden fixture，确保 harness 可以稳定拦截回退。

## 具体步骤
1. 读取新设计稿，确定正式模板结构、区块标题和占位符。
2. 抽出周报主题聚类和排序逻辑，优先用 formal 风格标签生成更具体的主题。
3. 重写周报 Markdown 组装逻辑，输出新设计要求的表格和列表。
4. 更新周报 LLM prompt/schema，让可选分析块服务新版结构，而不是旧“建议”章节。
5. 提升周报 review 规则与测试覆盖，必要时同步更新 golden fixture。
6. 跑定向 pytest、`git diff --check` 和 `harness-check`。

## 发现与意外
- 周报主题推荐如果直接复用旧 `topic_labels`，会回退到“电离层 / 热层”这类宽泛分类，因此需要单独的主题聚类辅助层。
- 现有测试样例里仍混有历史短标签（如 `电离层/TEC`），辅助层需要同时兼容短标签和 formal 风格标签。
- golden 周报基线只需要微调一处措辞差异即可收敛，结构层漂移已经被新版模板和 review loop 吸收。

## 决策记录
- 周报先按新结构重构程序和治理，再用真实 UI 运行结果做第二轮内容校准。
- 主题推荐优先用现有 formal 风格标签聚类，避免重新引入松散 pending 风格。
- 这轮保留现有 `ReportAnalysis` schema 字段名不变，降低兼容性风险；新版周报通过模板和代码重组这些分析块的用途。

- 已新增 `reporting_support.py`，用于从 formal 风格标签中抽取更具体的周报主题。
