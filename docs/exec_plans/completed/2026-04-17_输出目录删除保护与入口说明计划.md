# 计划：2026-04-17_输出目录删除保护与入口说明

## 目的 / 大图景
- 在项目根目录入口文档中明确文件操作边界与可写范围，避免用户误以为程序会任意修改或删除输出库文件。
- 为输出目录增加默认删除保护，确保任何会删除 `output_root` 下文件的逻辑都必须经过用户显式审核后才允许执行。
- 把这套保护纳入当前 harness 规则，避免后续标签治理、索引迁移或去重逻辑再次误删输出文件。

## 背景与定位
- 当前 README 和 PROJECT_CONFIG 说明了输出目录来源，但没有明确写出“默认不删除输出目录文件”的边界说明。
- 代码里仍有少量针对输出目录文件的删除路径，主要集中在单篇总结 DOI 去重和 article_index 旧页迁移。
- 这轮不改变输出结构、不重构周报或标签逻辑，只处理删除保护与根目录说明缺口。

## 工作范围
- `src/sciencemonitor/config.py`
- `src/sciencemonitor/article_summary_markdown.py`
- `src/sciencemonitor/article_index.py`
- `README.md`

- `tests/test_article_index.py`

## 非目标
- 不处理历史已经被删掉的输出文件恢复。
- 不改变 `tmp/`、`log/`、`data/` 等运行态目录的清理逻辑。
- 不引入 UI 审核流；本轮采用配置级显式审核开关。

## 计划中的工作
- 先建立统一的“输出目录删除是否允许”判断入口，默认禁止。
- 再把现有两处输出目录删除行为改成受该开关控制。
- 然后在 README 和 PROJECT_CONFIG 中明确写出文件操作边界与审核方式。
- 最后用定向测试和 harness-check 验证默认保护行为。

## 具体步骤
1. 在 `config/runtime.json` 的默认结构中增加安全开关，并提供统一 helper。
2. 修改单篇总结去重与 sub-index 旧页迁移逻辑，默认不删除输出目录文件。
3. 补充 README / PROJECT_CONFIG 中的边界说明和用户审核入口说明。
4. 新增回归测试，覆盖“默认阻止删除”和“显式允许删除”两种情况。
5. 运行定向 pytest、`git diff --check` 和 `harness-check`。

## 发现与意外
- 输出目录内真实删除路径只有两处：单篇总结 DOI 去重和 article_index 旧页迁移。
- `sync_out_library()` 会对 sub-index 页自动补导航内容，因此 legacy 迁移测试不能用“全文完全相等”断言。

## 决策记录
- 删除保护采用“默认关闭删除、用户显式开启”的配置审核方式，而不是静默删除后再记录日志。
- 保护范围限定在 `output_root` 下的真实输出文件；日志、缓存、临时文件清理不纳入本轮。
- `codex_local.sandbox` 与项目文件保护明确区分，避免把 provider sandbox 误解成输出目录保护。

## 结果与复盘
- 已在 `config/runtime.json` 与 `PROJECT_CONFIG.md` 中增加 `safety.allow_output_deletions`，默认 `false`。
- 已在 `README.md` 与 `PROJECT_CONFIG.md` 补充文件操作边界说明，明确输出目录默认不删文件。
- 单篇总结去重与 sub-index 旧页迁移都已改成受统一保护开关控制。
- 当前未引入 UI 审核流；用户审核入口是修改 `PROJECT_CONFIG.md` 同步块。
