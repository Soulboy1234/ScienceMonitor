# 计划：2026-04-10_无摘要文献周报分流计划

## 目的 / 大图景
- 让无法获取摘要或全文的论文不再生成伪单篇总结，避免在 Obsidian 输出中留下看似有效但实际只有元数据的文献卡片。
- 在周报中单独列出这些“未获取摘要/全文”的文献，保留监测记录，同时明确不可做内容解读。

## 背景与定位
- ASR 近期记录在 Crossref 中有题名和 DOI，但摘要字段为空；ScienceDirect 页面在本地请求中不可稳定抓取。
- 旧逻辑会生成 `#信息来源/仅元数据` 单篇总结，虽然已经避免错误标签，但仍会造成“有总结”的误解。
- 本轮只改变单篇总结与周报的分流规则，不引入 Elsevier API key 或浏览器自动抓取。

## 工作范围
- `src/sciencemonitor/article_summaries.py`
- `src/sciencemonitor/reporting.py`
- `src/sciencemonitor/pipeline.py`
- `src/sciencemonitor/reporting_template.py`
- `config/templates/daily_report_template.md`
- 相关单元测试与既有输出文件清理。

## 非目标
- 不抓取 ScienceDirect 受限全文。
- 不引入 Elsevier TDM 授权配置。
- 不重新生成所有周报或所有单篇总结。

- [x] 周报新增“未获取摘要/全文的文献”章节。
- [x] 删除既有 metadata-only 单篇总结文件并清理周报链接。
- [x] 补测试并运行 harness 检查。

## 计划中的工作
- 先调整单篇总结生成函数，让 metadata-only 记录不写文件。
- 再让周报接收完整窗口 rows，把无法总结的论文单独渲染。
- 最后清理当前输出目录中的既有 metadata-only 文件，并执行回归验证。

## 具体步骤
1. 在单篇总结生成阶段识别 `is_metadata_only_record` 并跳过写文件。
2. 在 `build_report` 增加 `missing_source_rows` 输入和对应渲染函数。
3. 更新周报模板和模板校验器，固定新增章节。
4. 更新 pipeline，让报告生成时传入完整窗口 rows。
5. 删除当前输出目录中 `#信息来源/仅元数据` 的既有单篇总结文件，并清理现有周报中的对应单篇链接。
6. 运行相关测试、熵检查与 harness gate。

## 发现与意外
- ASR 这批论文在 Crossref、OpenAlex、Semantic Scholar 中均无法稳定获得摘要；ScienceDirect 普通网页对本地程序请求不可稳定抓取。
- 现有 Obsidian article_index 中保留了已删除单篇总结的旧链接，需要运行 `index` 命令重建。

## 决策记录
- 元数据级文献保留在周报列表中，不进入重点推荐、主题聚焦和期刊重点论文列表。
- 当前不使用 Codex 网页检索能力作为程序内置能力，因为本地运行时无法直接复用该检索通道。
- 周报模板新增 `{{missing_sources_block}}`，让新增章节由模板固定，避免后续格式漂移。
- 单篇总结生成阶段在 LLM 调用前跳过 metadata-only 记录，避免为不可解读文章消耗 token。

## 结果与复盘
- 代码侧已实现 metadata-only 记录跳过单篇总结、周报单独列出。
- 当前输出目录中 5 个 ASR metadata-only 单篇总结已删除，当前周报已改为单独列出这些文献。
- 已同步重建 article_index，输出目录不再保留这些已删除单篇总结的旧链接。
