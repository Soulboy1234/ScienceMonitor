# 计划：2026-04-11_launcher误判启动失败修复

## 目的 / 大图景
- 修复双击 `启动操作面板.app` 时“面板其实已启动，但启动器误判失败”的问题。
- 把启动器的就绪探针从易漂移的页面标题，改成更稳定的机器标记，降低 UI 文案调整对启动器的破坏。

## 背景与定位
- 当前 `scripts/launchers/start_panel.sh` 和 `scripts/launch_config_ui.py` 都用旧标题 `<title>ScienceMonitor Config UI</title>` 判断 UI 是否就绪。
- 现在页面标题已经改成 `ScienceMonitor 控制台`，导致启动器等待超时后弹出失败提示，即使后台服务已正常起来。

## 工作范围
- `scripts/launchers/start_panel.sh`
- `scripts/launch_config_ui.py`
- `src/sciencemonitor/config_ui_page.py`
- `tests/` 下相关测试

## 非目标
- 本轮不重做 `.app` 包本身。
- 本轮不修改 UI 功能逻辑，只修复启动探针与校验。

## 进度
- [x] 步骤 1：确认日志与根因。
- [x] 步骤 2：加入稳定页面标记并更新两个 launcher 的探针。
- [x] 步骤 3：补测试与验证。

## 计划中的工作
- 先让页面输出稳定的机器标记。
- 再让 shell / python 两个 launcher 都改为识别这个标记。
- 最后补测试，避免后续再次被页面标题变更打断。

## 具体步骤
1. 在 config-ui HTML 中加入稳定标记。
2. 更新 `start_panel.sh` 与 `launch_config_ui.py` 的探针常量。
3. 增加定向测试并运行验证命令。

## 发现与意外
- 当前 `.app` 包内部的 AppleScript 明确调用仓库脚本 `scripts/launchers/start_panel.sh`，因此直接修仓库里的 launcher 脚本即可生效，不需要重做 `.app` 包。
- 之前已经在本机残留了一个旧版 `config-ui` 进程；因为它启动于修复前，页面里没有新的稳定标记，所以 launcher 会把它当成“不是 ScienceMonitor UI”。

## 决策记录
- 增加稳定机器标记 `<meta name="sciencemonitor-ui" content="config-ui">`，launcher 不再依赖页面标题文本。
- shell launcher 和 Python launcher 都统一识别这条 meta 标记，避免两套启动入口继续漂移。

## 结果与复盘
- 修复后，`scripts/launch_config_ui.py launch` 已能正确返回可用地址，不再误报启动失败。
- 已补测试覆盖页面标记和 launcher 探针常量。
- 已清理本机残留的旧 `config-ui` 进程，当前处于干净状态，可直接重新双击 `.app` 验证。
