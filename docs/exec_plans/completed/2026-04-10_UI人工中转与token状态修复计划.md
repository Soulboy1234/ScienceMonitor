# 计划：2026-04-10_UI人工中转与token状态修复

## 目的 / 大图景
- 修复控制台 UI 中“人工中转最新结果”错误混入周报单篇总结的问题。
- 让周报、深度解读、人工中转在任务完成后能自动刷新最新结果，减少用户手动刷新。
- 把 token 展示从“最近记录”升级为按日、周、月汇总的持久统计，避免 UI 重启后看不到刚运行过的消耗。
- 收口人工中转状态显示和 TODO 维护规则，避免已知问题后续丢失。

## 背景与定位
- 当前人工中转页面的最新结果只按“最新单篇总结”取文件，无法区分本地周报流程生成的总结和 ChatGPT 网页人工中转导入后生成的总结。
- UI 状态轮询已经能显示运行任务，但终态后部分结果面板不会自动更新。
- `config/analysis.json` 中的 Codex sandbox 只是传给 Codex CLI 的运行参数，不等同于 ScienceMonitor UI 对输出目录的写权限限制，界面需要解释清楚。
- 现有 token 展示偏向最近一次记录，不适合评估日、周、月消耗。

## 计划中的工作
- 先读现有 `config_ui` 状态采集和前端轮询，明确哪些字段需要进入 `/ui-status`。
- 再检查人工中转调用链，确认最小可行标记应落在生成报告 markdown 的 metadata/tag 中，而不是只在 UI 临时判断。
- 然后实现 token 统计持久化或复用已有运行日志，优先用已有日志源，避免引入重复记录系统。
- 最后补充测试和 TODO，确保新增但未做的事项不会从计划中消失。

## 具体步骤
1. 检查 `collect_config_ui_state`、`render_manual_view`、`config_ui.js` 和人工中转导入动作。
2. 增加 `#信息来源/GPT总结` 或等价 metadata 标记，并在人工中转页面最新结果筛选时只取带该标记的输出。
3. 扩展 `/ui-status` 返回字段，使前端轮询能更新 `latest_report`、`latest_deep_read` 和人工中转最新结果。
4. 梳理 token 记录来源，新增日、周、月汇总字段和 UI 展示；如无法还原历史精确 token，明确显示“从记录启用后累计”。
5. 精简人工中转状态卡，只展示等待响应数量，不展示 ready 数量。
6. 更新 `Todo.md` 使用规则：未完成事项及时加入、按重要性分级、完成后清理。
7. 运行定向测试、UI review 和 harness gate。

## 发现与意外
- 人工中转最新结果的旧逻辑确实会从“最新单篇总结”和“最新深度解读”里按 mtime 取最新文件，因此周报流程生成的新单篇总结会覆盖人工中转页面展示。
- token “未记录”的原因不是 UI 重启清空，而是旧检测只查找 `*token*usage*.md`，实际 Codex token 记录保存在 `log/llm_tmp/*_codex.stderr.log` 的 `tokens used` 行里。
- `Codex sandbox=read-only` 只约束 ScienceMonitor 启动的 `codex exec` 子进程，不限制 ScienceMonitor 主程序按配置写出报告、缓存和日志。
- 修改状态采集后 `config_ui_support.py` 曾超出单文件行数预算，因此拆出了 `config_ui_state_summary.py`，避免把 UI 支撑层继续堆大。

## 决策记录
- 人工中转生成的单篇总结和深度解读统一写入 `#信息来源/GPT总结`；已有历史产物若没有该标签，则用已导入人工中转请求的 DOI 做兜底匹配。
- 最新结果自动刷新不使用整页 `reload`，改为 `/ui-status` 返回结果文件 revision，前端只在 revision 变化时拉取对应结果卡片内容。
- token 统计优先复用 Codex stderr 日志，按本机日期汇总今天、本周、本月；目前只统计 Codex 日志，不伪造 OpenAI/OpenRouter token。
- 人工中转状态在 UI 中只展示等待响应的 pending 数，不再展示 ready 数。
- 本轮新增的代码量属于功能性增长，同时已拆出状态摘要模块；维护预算只小幅上调总行数阈值，不放宽单文件阈值。

## 结果与复盘
- 人工中转页面的“通过响应文件生成的最新结果”现在优先显示真实人工中转产物，不再直接混入周报流程生成的普通单篇总结。
- 周报、深度解读、人工中转结果卡片都带有可轮询的结果标识；后台任务完成或其他页面产物变化后，结果卡片会自动刷新。
- LLM 状态从“最近 token 记录”改成日/周/月 token 汇总，并增加了轻量柱状图。
- TODO 文件已改成按 P0/P1/P2 管理，并新增“周报输出内容和标准校准”作为后续 P1 任务。
- 本轮没有调整周报正文内容标准；这是下一步独立任务。
