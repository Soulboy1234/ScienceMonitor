# 计划：2026-04-11_token图列宽溢出修复

## 目的 / 大图景
- 修复总览页 token 图最后两天 bar 被挤出可视区的问题。
- 把“bar 超出图表边界”和“bar 像素高度为 0”纳入视觉审查，避免以后再次漏检。

## 背景与定位
- 当前在线服务中 `2026-04-09` 与 `2026-04-10` 两根柱体已经存在，但实际坐标一度超过图表右边界，因此用户在页面上看不到。
- 同时柱体还存在“数据和 inline height 都对，但实际像素高度为 0”的渲染问题。
- 用户又明确要求 x 轴固定为 `[x-27, x+2]` 的 30 天窗口，因此这轮要把窗口定义也上收到 token monitor。

## 工作范围
- `src/sciencemonitor/token_monitor.py`
- `src/sciencemonitor/config_ui_review.py`
- `src/sciencemonitor/ui_assets/config_ui.css`
- `src/sciencemonitor/config_ui_visual_review.py`
- `tests/test_token_monitor.py`

## 非目标
- 本轮不改 token 统计来源。
- 本轮不调整周报、深度解读等其他页面布局。

- [x] 步骤 2：修复 token 图 30 列网格的列宽与 gap 配置。
- [x] 步骤 3：补视觉审查，检查 bar 是否超出图表边界以及像素高度是否正确。
- [x] 步骤 4：重启面板并验证在线页面与 harness。

## 计划中的工作
- 先把 token monitor 的 30 天窗口定义改成“今天右侧预留 2 天”。
- 再收紧 token 图列间距，并移除不必要的最小列宽约束。
- 再修柱体高度渲染，让百分比高度真正映射成像素高度。
- 最后重启面板，用在线 HTML、截图和 harness 确认 4/9、4/10 两根 bar 已恢复可见。

## 具体步骤
1. 调整 token monitor 的时间窗口，让 30 天区间固定为 `[x-27, x+2]`。
2. 调整 token 图列宽配置，让 30 列在当前总览面板宽度内完整显示。
3. 修复网格项高度，使 bar 的百分比高度能够实际渲染出来。
4. 给视觉审查增加“非零 bar 溢出图表边界”和“bar 实际像素高度是否匹配数据”检测。
5. 重启 `config-ui` 并核对在线页面。
6. 跑 `harness-check` 收口。

## 发现与意外
- 当前视觉审查已能抓住坐标错位和标签越界，但还没有直接检查 bar 是否已经跑出 chart 容器，也没有检查实际像素高度是否为 0。
- 仅修正 x 轴范围不足以让 bar 可见，必须同时解决列宽溢出和高度渲染两个问题。

## 决策记录
- token 图窗口固定采用 `[今天-27, 今天+2]`，给最新实际数据右侧预留 2 天缓冲，不让最新 bar 贴在最右边界上。
- 优先修复 CSS 网格约束，而不是减少天数或折叠成更少列，因为 30 天是当前图的基本语义单位。
- 视觉审查增加像素级映射检查，避免“HTML 上有 height:93%，但实际页面 0px”的假通过。

## 结果与复盘
- 在线服务现已显示 4/9 与 4/10 两根 bar。
- 在线像素核对结果：
  - `2026-04-09` 柱高比例 `0.930`
  - `2026-04-10` 柱高比例 `0.880`
- 当前 token 图窗口已变为 `[今天-27, 今天+2]`，并在在线 HTML 中出现 `2026-04-11`、`2026-04-12` 两个未来空列。
- 最新总览截图已反映修复结果。
