# 计划：2026-04-23_周报偏好段落LLM化与监督

## 目的 / 大图景
- 将周报中的“与当前工作相关的重点”“对当前工作的可能启发”改成 LLM 生成候选内容，再由本地监督层审核后输出。
- 避免这两个段落继续使用过于模板化的规则句，提升内容判断力，同时保持可控和低熵。
- 保证周报链路里“LLM 负责分析、程序负责监督”的边界清晰。

## 背景与定位
- 当前周报的客观概览、主题推荐和期刊汇总已部分使用 LLM，但“与当前工作相关的重点”“对当前工作的可能启发”仍主要由本地规则生成。
- 用户明确要求这两个段落也应走 LLM 分析，并经过本地评估与监督后再输出。
- 本轮只调整周报偏好段落的生成与审核，不改 UI，不重构标签体系。

## 工作范围
- `src/sciencemonitor/llm.py`
- `src/sciencemonitor/llm_contracts.py`
- `src/sciencemonitor/reporting.py`
- 相关测试与必要的 golden fixture

## 非目标
- 不调整单篇总结内容
- 不重新设计周报整体模板结构
- 不修改抓取和深度解读链路

## 进度
- [x] 步骤 1：扩展 report schema，为两个偏好段落增加独立 LLM 字段
- [x] 步骤 2：在周报生成层接入“LLM 输出 + 本地监督”逻辑，并补测试
- [x] 步骤 3：重建 `2026-04-17 周报`，执行 harness 检查并归档计划

## 计划中的工作
- 先给 report analysis 增加新的结构化字段，并更新 prompt 合约。
- 再把周报里两个偏好段落切到新字段，同时保留本地兜底和质量审查。
- 然后重建真实周报，检查文案是否由 LLM 产生且经监督收敛。

## 具体步骤
1. 扩展 `ReportAnalysis`、JSON schema 和 prompt，要求 LLM 单独返回两个偏好段落。
2. 在 `reporting.py` 中增加监督函数，审核这两个段落的质量、相关性和禁用句式。
3. 补测试，覆盖“LLM 内容被采用”“低质量 LLM 内容被监督回退”两类情况。
4. 重建 `2026-04-17 周报`，并检查实际输出。
5. 运行 `pytest`、`harness-check`，完成后归档计划。

## 发现与意外
- `2026-04-17` 周报在切到新 schema 后，LLM 已实际返回 `preference_overview` 和 `work_implication`，但本地监督最初按过窄的相关论文集合校验，导致好文案被错误回退。
- 周报重建后，`Hanley` 和 `Neupane` 两篇 `auto` 单篇中残留的 alias 标签又回流了一次；当前已手动清理，后续需要单独定位其回流源头。

## 决策记录
- 这两个段落改成 LLM 生成，但最终输出仍由本地监督层兜底，不接受未经审核的原样直出。
- 若 LLM 结果过泛、过宽或包含弱相关内容，优先回退到本地收敛版本，而不是放任坏文案进入最终周报。
- 监督层对这两个段落的校验，采用“更宽的相关论文池 + 更窄的禁用句式/禁用主题”组合，而不是只拿前两三篇文章做硬匹配。

  - 周报生成层已切换到“LLM 输出 + 本地监督 + 本地兜底”模式。
  - 已重建 `2026-04-17 周报`，这两个段落现在实际使用 LLM 文案。
