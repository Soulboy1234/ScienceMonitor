# 计划：2026-04-28_Ollama单篇超时跳过续跑

## 目的 / 大图景
- 解决本地 Ollama 周报生成被单篇文章长时间超时阻塞的问题。
- 让单篇 Ollama 超时从“终止整份周报”改为“记录未完成项，跳过该篇，继续后续文章”。
- 在最终周报中明确列出未完成文章，保证输出可解释、可追踪、可后续补做。

## 背景与定位
- 2026-04-28 实测中，`gemma4:26b` 第 3 篇重试后成功，但第 4 篇再次单次请求超过 900 秒。
- 当前链路已能把 timeout 标记为 `paused_timeout`，但仍会停止整份周报。
- 用户明确要求改为单篇超时后跳过该篇，并在周报列出未完成文章。

## 工作范围
- 单篇总结生成循环的 timeout 处理。
- 周报生成时的未完成项传递与渲染。
- UI 周报运行状态中的跳过数量展示。
- 对应模板/审核规则/测试。

## 非目标
- 不降低 Ollama 超时时间。
- 不删除任何输出文件。
- 不改变非 Ollama provider 的普通错误语义。

- [x] 步骤 2：周报列出未完成文章

## 计划中的工作
- 新增未完成单篇总结的数据结构。
- `generate_article_summary_results()` 捕获 `AnalysisProviderTimeout(provider="ollama_api")`，记录未完成项并继续循环。
- `build_report()` 接收未完成项，并在“其他”区块中列出。
- UI 状态增加 `summary_skipped`，让用户能看到跳过数量。

## 具体步骤
1. 修改 `models.py`、`article_summaries.py`、`article_summary_progress.py`。
2. 修改 `pipeline.py` 和 `reporting.py`，传递并渲染未完成项。
3. 修改 `config_ui_report_jobs.py`、`config_ui_result_cards.py`、`ui_assets/config_ui.js`。
4. 更新 `daily_report_template.md` 与报告模板校验。
5. 补充 pipeline/reporting/config UI 测试并运行完整验证。

## 发现与意外
- Golden 周报样例保留了旧的“未获取摘要/全文的文献”标题和周报信息行，需要随模板行为同步更新。
- UI 进度中的 `summary_completed` 更适合作为“已处理数量”，否则跳过后进度会停滞；跳过数量单独用 `summary_skipped` 展示。

## 决策记录
- 只跳过 `ollama_api` 单篇分析超时；其他错误仍按原逻辑暴露。
- 进度中的 `summary_completed` 表示“已处理数量”，包括成功复用、成功生成和已记录跳过；另用 `summary_skipped` 显示跳过数量。

## 结果与复盘
- Ollama 单篇分析超时现在会被记录为未完成单篇总结，不再中止整份周报。
- 周报会在“未完成或未获取摘要/全文的文献”章节中分别列出“未完成单篇总结的文献”和“未获取摘要/全文的文献”。
- UI 周报运行状态与完成提示会显示未完成单篇数量，便于运行时判断是否需要后续补做。
- 非 Ollama provider 的错误处理语义保持不变，避免掩盖其他后端的真实故障。
