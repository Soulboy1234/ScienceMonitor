# 计划：2026-04-09_ui与计划治理第五轮

## 目的 / 大图景
- 把 `exec_plan` 模板和校验链路收紧成更符合 harness engineering 的机器治理层，避免计划格式继续漂移。
- 继续重构 `config-ui`，把布局、说明、provider 逻辑和审核链路统一到当前程序真实行为上。
- 在不放松现有 gate 的前提下完成这轮 UI 和 harness 整理，并通过完整维护检查。

## 背景与定位
- 当前 `exec_plan` 模板 source of truth 放在 `docs/exec_plans/TEMPLATE.md`，位置偏人类文档层，用户要求改为更 machine-facing 的模板位置。
- 当前计划虽然会被 `harness-check` 校验，但“模板在哪里、计划如何参与执行”表达还不够清晰。
- UI 已完成多轮重构，但仍存在版式不稳、说明不足、provider 逻辑不完整、设置页与程序真实能力不完全一致的问题。
- 本轮不仅要改 UI，也要同步修改底层代码和审查链路，避免 UI 只改表面。

## 工作范围
- `config/templates/` 下新增并接管 `exec_plan` 模板 source of truth。
- `src/sciencemonitor/exec_plan_review.py`、`src/sciencemonitor/harness.py`、相关测试与文档。
- `src/sciencemonitor/config_ui*.py`、`src/sciencemonitor/ui_assets/*`。
- `src/sciencemonitor/llm.py`、相关配置保存逻辑与测试。
- 必要的 `CHANGELOG.md`、`PLANS.md`、`docs/exec_plans/README.md`、`docs/workflow_specs` / `docs/user_guides` 引用说明。

## 非目标
- 不做新的报告产出风格重构。
- 不做周报/深读业务规则的大改版，只修正与 UI 控制和 provider 逻辑直接相关的部分。
- 不做 GitHub 发布或版本打 tag。
- 不处理与本轮无关的 `Todo` 增强项。

## 计划中的工作
- 先处理 `exec_plan` 模板 source of truth 和计划治理。
- 再处理 UI 结构与视觉问题，确保页面可读性和信息一致性。
- 接着同步修改 provider 与设置保存逻辑，避免 UI 伪配置。
- 然后补 UI 审查模块与测试，让这轮改动进入 harness gate。
- 最后跑完整检查并把计划归档。

## 具体步骤
1. 把 `exec_plan` 模板迁移到 `config/templates/exec_plan_template.md`，并更新 `exec_plan_review`、文档和测试。
2. 为 `exec_plan_review` 增加活动计划摘要能力，让 `harness-check` 能显示当前活动计划路径与未完成步骤概况。
3. 重构 `config-ui` 的导航、总览、周报、深度解读、人工中转、设置页面结构与样式。
4. 为关键表单项增加 hover 说明，并统一面板间距、字体、滚动与内容渲染。
5. 在 `llm.py` 和设置保存逻辑中新增 `openrouter_api`，并调整 provider 相关 UI 和状态显示。
6. 增加 UI 审查模块，检查关键导航、页面块、tooltip、provider 面板和结果渲染是否符合约束。
7. 运行 `doctor`、`entropy-check`、`harness-check`、`maintenance-check` 和 `pytest`，修复发现的问题后归档计划。

## 发现与意外
- `exec_plan` 模板虽然存在，但放在 `docs/exec_plans/` 时更像“给人读的参考文档”，不利于机器层把它视为 source of truth。
- 计划是否真的参与执行，关键不在“文件存在”，而在 harness 是否能读出活动计划的当前状态并把它反馈到检查结果里。
- UI 重构不仅是页面问题；一旦设置项变动，`llm.py`、保存逻辑、文档同步和错误提示都要一起收口，否则会出现“界面说一套、程序跑另一套”。
- 新增 `openrouter_api`、UI 审查模块和计划审查模块后，总包预算出现真实上升；这不是单文件失控，而是新增能力带来的预算滞后。

## 决策记录
- 把 `exec_plan` 模板迁到 `config/templates/exec_plan_template.md`，`docs/exec_plans/TEMPLATE.md` 仅保留指向说明。
- `harness-check` 增加 `exec_plan` 活动状态摘要，让当前计划的已完成项、未完成项和下一步能够直接出现在 gate 输出里。
- 新增 `config_ui_review.py`，把 UI 的关键导航、禁用项、tooltip 和页面块纳入 harness 审核，而不是只靠人工看页面。
- 设置页不再把 `chatgpt_web_manual` 作为全局 provider 选项；人工中转保留在独立工作流里。
- 底层分析后端新增 `openrouter_api`，同时移除已无实际意义的 `enabled`、`max_items_per_run`、`max_papers_in_prompt`、`max_input_chars` 等旧控制项。
- 保持模块级预算不放松，仅对总包预算做小幅上调，以反映新增的真实工程能力。

## 结果与复盘
- `exec_plan` 输出稳定性已进入 harness：模板 source of truth 固定、活动计划状态可见、结构校验自动化。
- UI 已完成一轮系统性收口：导航更简洁、总览信息更聚焦、周报/深度解读/人工中转都有更明确的面板结构和渲染结果。
- 设置页和底层逻辑已重新对齐：provider 语义清晰，OpenRouter 已接入，手动中转不再冒充全局分析后端。
- 这轮最大的价值不是“页面更好看”，而是把 UI 和 harness 一起纳入了可审核、可测试、可维护的治理链路。
- 剩余工作不再是结构性阻塞，而是后续版本继续打磨交互和视觉细节。
