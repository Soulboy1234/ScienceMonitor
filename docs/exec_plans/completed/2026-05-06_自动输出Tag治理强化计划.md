# 计划：2026-05-06_自动输出Tag治理强化

## 目的 / 大图景
- 整治自动生成的单篇总结、深度解读和周报中的不合格 tag，并同步加固后续 tag 生成与 pending 记录链路。
- 目标是让抽象概述 tag、错误根 tag、重复路径 tag 不再反复进入输出和 pending。

## 背景与定位
- 当前 `pending_tags.md` 中仍有 `对象/空间天气/地磁暴`、`对象/物理机制/Joule加热`、`模型/物理模型`、`对象/卫星` 等低价值或误根 tag。
- 现有自动审计覆盖单篇总结和深度解读，但周报中缩进的 `- 标签：` 行没有被 `extract_summary_tags()` 捕获。
- 用户明确要求不是单次清扫，而是同步强化生成规则和稳定性。

## 工作范围
- tag 治理与审核：`src/sciencemonitor/tag_governance.py`、`src/sciencemonitor/tag_review.py`
- 周报 tag 派生与重写：`src/sciencemonitor/reporting.py`、`src/sciencemonitor/reporting_support.py`
- CLI 入口：`src/sciencemonitor/cli_support.py`
- prompt 约束：`src/sciencemonitor/llm_contracts.py` 或当前实际 prompt 构建模块
- 测试：`tests/test_tag_review.py`、`tests/test_tag_candidates.py`、`tests/test_reporting.py`
- 自动输出：`auto/article_summaries`、`auto/deep_reads`、`research_reports`、`article_index`

## 非目标
- 不改 `manual/` 手工笔记。
- 不自动转正 pending tag。
- 不重跑 LLM 正文，不重写正文内容。
- 不做全局 tag 层级上限。

## 发现与意外
- 周报中的缩进 `- 标签：` 行此前没有被输出审计正确捕获；修复后周报参与整治，但 pending 仍只统计单篇总结和深度解读。
- 初版周报审计按整篇文件聚合所有推荐论文 tag，导致不同论文行的父子标签互相压制并产生误报；已改为逐行审计，和实际重写粒度一致。
- 真实输出整治后，目标残留检查未发现 `对象/空间天气/地磁暴`、`对象/物理机制/Joule加热`、`模型/物理模型`、`对象/卫星`、`仪器/磁力计`、`应用/空间天气/预报`、`对象/极区/极光/流光` 等问题 tag。

## 决策记录
- pending 只统计 `auto/article_summaries` 和 `auto/deep_reads`，周报作为派生输出不重复计数。
- 采用“只留高价值候选”策略：无法归并且不够具体的抽象 tag 不进入 pending。

## 结果与复盘
- 已增加持久治理规则：常见误根 tag 稳定归并到正式 tag，抽象概述 tag 不进入输出或 pending，业务化预报、卫星轨道衰减、仪器/任务类 tag 继续走证据门槛。
- 已强化单篇总结、深度解读通用 prompt、Ollama 深读 final/revision prompt 的 tag 规则，强调闭集优先、实体优先、证据优先、抽象概念不进 tag。
- 已扩展 `tag-candidates --reconcile-output`，执行顺序为重写自动单篇总结、深度解读、周报派生 tag 行，重建 article index，并刷新 pending tag 文件。
- 已运行真实自动输出整治，扫描 64 个 Markdown 输出文件；最终 `config/pending_tags.json` 保留 54 个候选，均不含本轮明确禁止的抽象概述和误根 tag。
