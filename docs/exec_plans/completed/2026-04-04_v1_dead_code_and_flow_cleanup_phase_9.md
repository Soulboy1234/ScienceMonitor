# V1 Dead Code And Flow Cleanup Phase 9

## Purpose / Big Picture

第九阶段不再以“大文件拆分”为主，而是转向 `v1.0.0` 前的第二类降熵工作：

- 清理拆分后遗留的死代码、旧引用和重复路径
- 继续归档确实不再参与运行的旧材料
- 在不引入碎片化模块的前提下，收紧运行链路和维护预算

目标是把当前结构优化成果稳固下来，避免“文件拆小了，但旧逻辑残留、引用绕路、无用材料继续堆积”。

## Decision Log

- 当前不继续追求把主模块拆得更小，优先做“删除无用部分”和“缩短真实运行路径”
- 只有在发现新的清晰边界时才继续拆分模块
- 维护预算继续作为约束，但不把总包行数压缩作为唯一目标
- 首轮只读审计显示：`no_need_for_v1.0.0/` 和旧 `docs/archive/` 的引用目前只出现在文档、计划和 changelog 中，暂未发现运行时代码耦合
- 第二轮静态扫描清掉了一批确认无用的导入和死参数；剩余命中的大多是跨模块兼容导出，后续应显式标注，而不是误删
- 第三轮清理把多处内部调用和测试改成直连新子模块，删除了一批历史兼容转发；`package_total_max_lines` 仅上调到 `12140`，用于容纳新增的 unused-import 审计与维护逻辑，单模块预算继续保持收紧
- 最终 gate 结果：`entropy-check`、`maintenance-check --auto-repair --max-passes 2`、全量 `pytest` 均通过，Phase 9 收尾条件已满足
