# 计划：2026-04-28_Ollama周报超时与UI状态修复

## 目的 / 大图景
- 修复 `ollama_api / gemma4:26b` 生成周报时单篇总结超时后被标记为普通错误的问题。
- 让本地模型长时间生成时，UI 能持续显示运行时长、当前文章、模型和可续跑提示。
- 保留已完成单篇总结，确保用户再次运行时可通过“跳过已生成总结”继续推进。

## 背景与定位
- 2026-04-28 UI 实测中，provider 成功切到 `ollama_api`，抓取阶段正常，Ollama 成功完成前 2 篇单篇总结。
- 第 3 篇 `Medium-Term Forecasting of Solar F10.7 Using VMD-SOBI-DLinear Hybrid Model` 在 Ollama 请求阶段 `timed out`。
- UI 状态在长请求期间 `elapsed_seconds` 不更新，容易误判为卡死。

## 工作范围
- Ollama/API 超时异常语义。
- 周报后台任务状态处理。
- 周报运行状态 UI 展示。
- Ollama 默认超时时间与设置保存逻辑。
- 对应测试与 harness 验证。

## 非目标
- 不重跑完整周报。
- 不删除刚刚生成的两个单篇总结。
- 不回滚用户通过 UI 切换到 `ollama_api` 的本地配置。

## 进度
- [x] 步骤 1：将 Ollama timeout 转成可续跑状态
- [x] 步骤 2：优化 UI 长任务状态实时显示
- [x] 步骤 3：更新测试与验证

## 计划中的工作
- 新增 provider timeout 类型，让周报 worker 能区分“本地模型超时”和普通程序错误。
- 将 Ollama 默认 timeout 提高到更适合本地 26B 模型的值，同时保留 UI 可配置。
- 在 UI 状态汇总层动态计算 running 任务的 elapsed，避免长请求期间时间停住。
- 在周报状态卡中显示 `paused_timeout` 为可续跑，而不是普通 error。

## 具体步骤
1. 修改 `llm.py` / `llm_api_support.py`，规范 Ollama timeout。
2. 修改 `config_ui_report_jobs.py`，捕获 timeout 并写入 `paused_timeout` 状态。
3. 修改 `article_summary_progress.py` 和状态卡，让 Ollama 显示模型和 token 均值。
4. 修改 `config_ui_support.py`，动态刷新 running job elapsed。
5. 更新 `tests/test_config_ui.py`、`tests/test_llm.py`，跑定向测试和 harness-check。

## 发现与意外
- 当前测试工程会复制本机 `config/analysis.json`，因此 provider 被 UI 切到 `ollama_api` 后，原先假设默认 provider 为 `codex_local` 的测试会失效。已把对应测试改为显式设置 provider，减少本地配置对测试的干扰。
- Ollama 的超时更接近“本地模型响应过慢导致的可恢复暂停”，不应进入普通 error，否则用户会误以为已完成结果不可复用。

## 决策记录
- Ollama timeout 不等同于普通 bug；它是可恢复中断，已完成总结应保留。
- `ollama_api.timeout_seconds` 默认从 300 秒提高到 900 秒，适配本机 26B 模型；仍保留 UI 可调。
- 周报 UI 对 `paused_timeout` 使用可续跑提示，下一次运行保持“跳过已生成总结”即可继续，不重做已完成文章。

## 结果与复盘
- 新增 `AnalysisProviderTimeout`，Ollama 请求超时后会被周报 worker 捕获并写入 `paused_timeout`。
- 周报运行状态会保留来源计数、单篇总结进度、当前文章、模型、平均 token，并在长请求期间动态更新运行时长。
- API 类 provider 的单篇总结 token 均值改为读取 `log/token_monitor/api_usage.jsonl` 的增量记录，`ollama_api` 也能显示平均单篇 token。
- 本次没有重跑完整周报，也没有删除已生成的两个 Ollama 单篇总结。
