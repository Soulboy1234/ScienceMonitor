# 计划：2026-04-29_UI深度解读体验优化

## 目的 / 大图景
- 修复深度解读 UI 在长任务期间像卡住的问题，让页面显示可轮询的实时状态。
- 改善批量深度解读入口，支持点击选择文件夹或拖拽文件夹填入路径。
- 修复 Ollama 深度解读 evidence 阶段非法结构化输出导致 UI 失败的问题。

## 背景与定位
- 当前用户在 UI 中运行深度解读时，浏览器会保持表单请求等待，视觉上像页面卡死。
- 批量深度解读已有路径输入入口，但手动粘贴本机路径成本高。
- 本轮报错来自 `deep_read_evidence_v2_*` 的 Ollama 结构化 JSON 解析失败，需要结合已有 Ollama 质量模式兜底处理。

## 计划中的工作
- 先读现有 UI 路由、状态接口和 JS 行为，沿用已有 report job 模型。
- 将深度解读和批量深度解读提交改为后台任务，页面即时返回并通过状态接口刷新。
- 在批量表单旁增加浏览器可用的 folder picker 和拖拽区域，无法拿到绝对路径时给出明确提示。
- 扩展 Ollama JSON 提取/修复逻辑，优先处理常见 markdown、尾随逗号或截断前后缀问题。
- 用聚焦测试覆盖 UI 行为和解析修复。

## 具体步骤
1. 检查 `config_ui_report_jobs.py` 是否可复用为通用 UI job。
2. 检查 `/ui-status` 和 `config_ui.js` 如何刷新任务进度。
3. 修改深度解读 action 或路由，使长任务不阻塞浏览器表单请求。
4. 修改深度解读页面 HTML、CSS、JS，增加进度展示和文件夹选择/拖拽。
5. 修改 Ollama 结构化输出解析，保存诊断文件并尽可能修复可恢复 JSON。
6. 跑相关 pytest、py_compile 和必要的 harness 子集。

## 发现与意外
- 深度解读表单原先在 POST 请求内同步执行 `run_deep_read()`，浏览器会一直等待后端 LLM 调用完成，因此视觉上像页面卡住。
- 用户提供的 invalid output 文件不是大段缺失，而是 `secondary_findings` 数组末尾多了一个尾随逗号；这是可保守修复的 Ollama 常见 JSON 退化。
- 浏览器标准环境通常不能把“选择文件夹”转换成本机绝对路径；本轮采用目录上传到本地临时目录的方式，保留手动路径输入作为高级入口。

## 决策记录
- 深度解读采用独立 `deep_read_job` runtime state，不复用 `report_job` 字段，避免周报状态卡片和深读状态卡片互相污染。
- 批量文件夹选择优先走 multipart 目录上传；如果浏览器提供非标准 `File.path`，JS 会尝试回填路径，否则直接提交上传副本。
- Ollama JSON 修复只处理结构安全的尾随逗号和非法反斜杠，不尝试猜测缺失字段或补写语义内容。

## 结果与复盘
- 深度解读和批量深度解读都会立即启动后台线程，页面通过 `/ui-status` 轮询显示当前阶段、耗时、批量进度、当前 PDF、全文来源和最新输出。
- 批量深度解读表单新增文件夹选择/拖拽入口，同时保留本地路径输入。
- Ollama structured output 解析现在会修复 evidence 阶段常见尾随逗号，用户提供的错误类型可恢复。
- 本轮没有改变深度解读 Markdown 模板和正式输出结构。
