# 计划：2026-04-09_UI周报栅格修复

## 目的 / 大图景
- 修复周报页首行栅格类缺失导致的实际布局崩坏问题。
- 把“布局类存在但未定义”纳入 UI harness 审核，避免类似问题再次通过检查。

## 背景与定位
- 用户在周报页看到首行面板被压成异常窄列，说明实际 CSS 栅格没有生效。
- 当前 harness 已检查周报页包含窄视口断点，但没有检查页面实际使用的 `span-*` 类是否存在对应样式。

## 工作范围
- `src/sciencemonitor/ui_assets/config_ui.css`
- `src/sciencemonitor/config_ui_review.py`
- `tests/test_config_ui_review.py`
- `docs/exec_plans/completed/2026-04-09_UI细化第八轮计划.md`

## 非目标
- 不重做周报页信息架构。
- 不调整周报业务逻辑和抓取逻辑。
- 不做版本发布和 GitHub 同步。

## 进度
- [x] 补齐周报页实际使用的栅格类定义。
- [x] 增加 UI review 对缺失栅格类的检查。
- [x] 更新测试并跑一轮校验。
- [x] 回填并归档计划。

## 计划中的工作
- 先修 CSS，再补 review 和测试。
- 完成后至少跑 `pytest tests/test_config_ui_review.py -q`、`harness-check` 和 `git diff --check`。

## 具体步骤
1. 为 `.span-3` 和 `.span-9` 添加栅格规则。
2. 在 `config_ui_review` 中检查周报页依赖的栅格类定义。
3. 在测试中锁定这些类和 review 行为。
4. 跑校验并归档计划。

## 发现与意外
- 周报页使用了 `span-9` 和 `span-3`，但公共 CSS 栅格层里根本没有这两个类定义。
- 之前的 harness 检查到了“周报页用了这些类”，但没有检查“这些类是否真的有样式实现”。

## 决策记录
- 不重做周报页结构，先补齐缺失的栅格定义。
- UI harness 增加对关键栅格类定义本身的检查，而不只检查类名出现在 HTML 中。

## 结果与复盘
- 周报页现在有了实际可用的 `3:1` 栅格定义，窄视口下再由断点规则接管堆叠布局。
- 这次问题说明当前 UI harness 还不是完整视觉回归，只能通过“关键结构 + 关键样式”逐步补齐护栏。
