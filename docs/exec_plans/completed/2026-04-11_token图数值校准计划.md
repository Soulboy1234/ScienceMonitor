# 计划：2026-04-11_token图数值校准

## 目的 / 大图景
- 修复总览页 token 图“视觉形式对了，但数值映射不对”的问题。
- 把这类数值映射错误纳入 harness，避免以后只检查 DOM 和布局却漏掉数值正确性。

## 背景与定位
- 当前 token 图的柱高和坐标轴读数存在不一致，说明图表的缩放基准和坐标轴刻度不是同一个上限。
- 当前横轴标签会把最后一天的空值日期显示成末尾锚点，导致 4/9、4/10 的柱子落在 4/11 标签附近，语义误导。
- 这类问题之前没有被 harness 抓住，说明视觉检查和测试只覆盖了结构，没有覆盖数值映射。

## 计划中的工作
- 先修柱高缩放基准。
- 再修横轴标签锚点选择。
- 最后补针对“数值一致性”的 harness 检查。

## 具体步骤
1. 让柱高缩放使用与纵轴一致的 chart max，而不是原始最大值。
2. 让横轴标签优先标注有实际数据的日期，避免空值末日标签误导。
3. 增加 token 图数值映射测试和视觉/几何校验。
4. 重启 config-ui 并复核。

## 发现与意外
- 柱高错误的直接原因是渲染层把柱子按 `raw max_tokens` 缩放，但纵轴刻度按 `_build_token_tick_values()` 取整后的 `top tick` 显示，两者基准不同。
- 横轴标签错误的直接原因是标签策略始终保留“最后一天”作为末尾锚点，即使最后一天没有 token；这会把 4/9、4/10 的柱子误挂到 4/11 标签下。
- 之前 harness 漏掉这类问题，是因为视觉审查只看 DOM 结构和布局，没有校验“柱高比例是否匹配纵轴数值”和“最后一个可见标签是否对应最后一个非零柱”。

## 决策记录
- 柱高统一按 `chart_scale_max = tick_values[0]` 缩放，保证柱体和坐标轴使用同一个上限。
- 横轴末尾标签优先使用“最后一个非零日期”，只有全为空值时才退回最后一天。
- 视觉审查新增两条数值类检查：
  - `token_chart_value_mapping`
  - `token_chart_last_label_mismatch`

## 结果与复盘
- 当前服务端 token 图已输出正确的柱高：
  - `2026-04-09` 为 `height:93%`
  - `2026-04-10` 为 `height:88%`
- 当前服务端末尾横轴标签已从 `4/11` 修正为 `4/10`。
- harness 现在不只检查 token 图的结构和溢出，还会检查数值映射和末尾标签语义。
