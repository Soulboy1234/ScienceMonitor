# 计划：2026-04-28_深度解读PDF文件夹批处理

## 目的 / 大图景
- 给深度解读增加“PDF 文件夹批处理”能力，让用户指定一个文件夹后，程序按顺序对其中每篇 PDF 生成深度解读。
- 该功能复用现有单篇深度解读链路，避免另起一套输出格式、标签审核和模板审核逻辑。

## 背景与定位
- 当前深度解读只支持单篇 PDF、DOI、题目或 URL。
- 用户希望从 UI 给定一个含多篇论文 PDF 的文件夹，由程序依次处理。
- 当前可能有周报任务在 UI 后台运行，本轮不重启面板、不中断后台任务。

## 工作范围
- 修改 `src/sciencemonitor/deep_reads.py`，新增 PDF 枚举和批处理执行函数。
- 修改 CLI 入口，提供可脚本化的文件夹批处理命令。
- 修改 UI action 与深度解读页面，提供文件夹路径入口。
- 补充对应单元测试。

## 非目标
- 本轮不重构深度解读的 LLM 提示词和内容风格。
- 本轮不改变已有单篇深度解读输出标准。
- 本轮不强制引入后台队列和实时批处理进度；如后续实际使用发现 UI 同步执行体验不足，再单独做后台任务化。

## 计划中的工作
- 先把批处理能力放在 `deep_reads.py`，保证所有入口复用同一行为。
- 批处理按文件名稳定排序，默认只处理当前文件夹内 PDF，支持可选递归。
- 单篇失败不终止批处理，结果汇总成功数、失败数和失败文件。
- UI 入口只负责收集文件夹路径和参数，不复制深度解读业务逻辑。

## 具体步骤
1. 检查现有单篇深度解读函数的参数、输出和失败语义。
2. 新增 `run_deep_read_folder`，依次调用 `run_deep_read`，并在末尾同步输出索引。
3. 给 CLI 增加 `deep-read-folder --folder ...` 命令。
4. 给 UI 深度解读页面增加文件夹批处理表单和 action。
5. 补充单元测试覆盖 PDF 排序、失败不中断、UI action 参数传递。
6. 运行目标测试、`git diff --check` 和必要 harness 检查。

## 发现与意外
- 当前深度解读 UI 仍是同步提交模型任务；批量 PDF 数量较多时，页面会等待较久。后续如果实际使用体验不足，需要单独做后台任务队列和进度显示。

## 决策记录
- 批处理复用单篇深度解读函数，不新建第二套模板渲染逻辑。
- 默认非递归处理，避免误扫大目录；用户可显式选择包含子文件夹。
- 批处理中每篇文章默认用 PDF 文件名作为题目兜底，便于没有 DOI 的本地论文也能进入现有链路。
- 为保证报告中的 Obsidian 索引挂接逻辑不退化，批处理中的每篇仍保留单篇完整同步流程，不改成最后统一回填。

## 结果与复盘
- 已新增 `run_deep_read_folder` 和 `list_deep_read_pdf_files`。
- CLI 新增 `deep-read-folder --folder ... [--recursive]`。
- UI 深度解读页新增“PDF 文件夹批量深度解读”表单，并纳入视觉审查和功能审查。
- 单篇失败不会中断批处理，会在最终结果中汇总失败 PDF。
