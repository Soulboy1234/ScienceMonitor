# 计划：2026-04-28_周报词云与深度解读UI错误修复

## 目的 / 大图景
- 修复当前周报中词云资源缺失、同一期刊被拆分统计、以及 UI 无法启动深度解读的问题。
- 这三处都属于运行链路 bug，会直接影响用户使用和输出可信度。

## 背景与定位
- 最新周报引用 `research_reports/assets/2026-04-28 标签词云.png`，但实际输出目录中没有该图片。
- 周报中 `JGR: Space Physics` 与 `Journal of Geophysical Research: Space Physics` 被当成两个期刊。
- UI 深度解读提交时报 `Cannot be converted to bool.`，疑似上传字段对象被直接做布尔判断。

## 工作范围
- 周报词云生成与引用路径逻辑。
- 周报期刊名称归一化逻辑。
- UI 深度解读 action 的上传文件判断逻辑。
- 对应测试与 harness 检查。

## 非目标
- 不重写周报内容风格。
- 不改变深度解读报告模板。
- 不清理或删除用户输出库中的历史报告。

## 计划中的工作
- 先修 UI 提交错误，这是确定性 bug。
- 再检查周报词云文件为何没有生成或为何被错误引用。
- 之后统一周报内所有按期刊聚合的位置，避免只修统计表但不修期刊主题汇总。
- 最后跑目标测试、UI 审查和 harness。

## 具体步骤
1. 读取最新周报和 assets 目录，确认缺失资源与引用格式。
2. 检查 `reporting.py` 中词云生成、清理和引用。
3. 检查 `config_ui_actions.py` 中文件上传判断。
4. 检查 `reporting.py`、`reporting_support.py` 和 LLM prompt 中的期刊名称传递。
5. 补测试覆盖 JGR 全称/短称合并、词云资源引用存在、空上传深度解读不报 bool 错。
6. 跑验证。

## 发现与意外
- 词云缺失不是 Pillow 生成失败，而是 `build_report` 在新报告写盘前调用了清理逻辑；当本机允许输出删除时，新图会被误判为未引用并删除。
- UI 深度解读报错来自 `cgi.FieldStorage` 不允许直接转 bool，真实上传 PDF 时会触发 `Cannot be converted to bool.`。
- Harness 额外暴露了 golden fixture 需要跟随期刊缩写归一化更新，以及 4 个已有 auto 输出文件的标签顺序需要按当前审核器修正。

## 决策记录
- 期刊显示名优先使用已有 `abbreviate_journal_name` 统一成稳定缩写，避免 Crossref 返回全称/短称造成拆分。
- 词云清理从“报告构建阶段”移到“报告写盘后”，确保新报告已经引用新资源后再清理旧资源。
- 当前已生成的 `2026-04-28 周报.md` 和 `latest.md` 做确定性修复，只修复资源缺失和期刊名拆分，不重跑 LLM 周报。

## 结果与复盘
- 已修复周报词云资源被误删问题。
- 已修复 JGR 全称与短称在周报统计、主题分布、期刊汇总、LLM schema 和 prompt 中被拆分的问题。
- 已修复 UI 深度解读真实上传 PDF 时的 bool 转换错误。
- 已补生成当前 2026-04-28 周报缺失的词云图，并修正当前 `2026-04-28 周报.md` 与 `latest.md` 中的 JGR 拆分。
