# Literature Directory Integration Guide

## 目的

这份文档用于约束新文献笔记如何稳定整合进你现有的 Obsidian 文献系统。它不讨论单篇笔记正文怎么写，而是讨论：

- 文件该放哪
- 文件名该怎么定
- 该挂到哪些目录页
- 更新目录页时哪些可以动，哪些不要乱动

## 现有系统的三层结构

当前文献系统至少有三层：

1. 单篇笔记层：`文件 - 笔记/`
2. 专题目录层：`文件 - 目录/`
3. 总目录层：`笔记目录.md`

项目当前还有一套位于“输出根目录”的“输出侧索引”用于程序生成内容。输出根目录由 [../config/paths.json](../config/paths.json) 中的 `output_root` 指定：

1. `manual/`：人工整理笔记副本
2. `auto/article_summaries/`：自动单篇总结
3. `auto/deep_reads/`：自动/交互式深读
4. `article_index/index.md` 与 `article_index/sub_index/`：输出侧主题索引

这里最重要的原则是：

> `tag` 不是目录，目录也不是 `tag`。它们是并列存在的两套检索系统。

因此，新笔记整合不能只写正文和标签，还要判断它应该从哪些专题目录入口被重新找到。

## 核心硬规则

### 1. 单篇笔记默认放在 `文件 - 笔记/`

不要把单篇文献笔记直接混放到根目录，也不要放到 `文件 - 目录/`。

### 2. 目录页默认放在 `文件 - 目录/`

目录页负责主题导航，不和单篇笔记混层。

### 3. 文件名必须稳定，目录链接必须精确

单篇笔记文件名默认采用：

`作者姓 年份 - 期刊缩写 - 中文功能性概括.md`

目录页中的链接必须直接使用文件名 stem，例如：

`[[Aa 2012 - JGR.SP - 热层密度对磁暴响应的南北半球不对称性]]`

不要在目录页里重新发明另一套标题。

如果输出侧使用的是带路径的 wikilink，例如：

`[[manual/Aa 2012 - JGR.SP - 热层密度对磁暴响应的南北半球不对称性|Aa 2012 - JGR.SP - 热层密度对磁暴响应的南北半球不对称性]]`

则显示别名只保留页名本身，不显示路径；若文件名末尾附带 ` - 重要` 这类状态尾缀，显示别名里默认去掉，只把它当文件管理信息。

### 4. 新笔记优先挂叶子目录，不直接挂父目录

默认优先插入更具体的叶子页，例如：

- 优先 `2.6 - 磁暴`
- 而不是只挂 `2 - 热层电离层耦合系统`

父目录主要负责列子目录，不拿来堆单篇笔记。

### 5. 每篇笔记默认 1 个主目录 + 0-2 个辅助目录

通常不建议超过 3 个目录入口。目录入口宁可少挂，但每个入口都必须真实有检索价值。

非地球文献另加一条默认规则：

- 先挂入 `6 - 其他行星` 下对应星球的叶子页
- 若该星球下还有更细页，例如火星的 `6.4.1 - 行星际环境的影响`，优先继续下钻
- 只有在确有交叉主题价值时，再补 `7 - 太阳与日球层`、`8 - 波粒相互作用`、`9 - 高能粒子与辐射带`
- 地球主体目录 `1-4` 默认不保留非地球条目

### 6. 目录整合看“主问题”，不是看标签镜像

是否进入某目录，看的是：

- 这篇文章的主问题是什么
- 你未来会从哪个专题入口重新找它
- 它在该目录里是否和已有条目属于同类材料

所以：

- 有 `#磁暴` 不一定必须进 `2.6 - 磁暴`
- 有 `#建模/机器学习` 也不一定以 `2.3 - 热层建模` 为主入口

### 7. 更新目录页只做最小必要修改

如果用户没有明确要求，不要顺手：

- 重排整个目录页
- 删除历史空行或占位条目
- 改写已有说明文字
- 把特殊目录页统一成新格式

目录更新的原则是：

> 只做让新笔记能被稳定纳入系统所必需的最小修改。

### 8. `manual/` 默认只修链接，不改正文

输出根目录下的 `manual/` 是人工整理内容的阅读副本。默认可以：

- 修正文内 Obsidian 双向链接
- 修正当前仓库里真实存在的目标文件路径
- 为了维持索引分类稳定，只对首行标签串做最小必要修正，例如补或移除 `#其他行星/...`

默认不要：

- 改写原有摘要
- 重排段落
- 改标签或增删正文判断

如果 PDF、图片或附件资源本身不在当前仓库，就先不要硬修这些资源链接。

### 9. 自动输出也要纳入 `article_index/`

后续新的自动单篇总结和深读，不应只放在 `auto/...` 下，还应继续同步到：

- `article_index/index.md`
- `article_index/sub_index/`

执行规则是：

- 优先挂到已有叶子主题页
- 没有合适叶子页时，可先挂到现有父主题页
- 如果现有体系确实容纳不了，再新建 `sub_index/<主题>.md`
- 新建后要把它再加入 `index.md`
- 新建 `sub_index` 时要延续现有编号顺序；如果属于 `其他行星`，先放到 `6 - 其他行星` 下，再按星球细分
- `index.md` 与 `sub_index` 中的链接显示文字默认只显示页名，不显示路径

## 默认工作流

后续新增一篇笔记时，默认按下面顺序处理：

1. 生成或整理单篇笔记正文
2. 确定规范文件名
3. 打标签
4. 选出 1 个主目录
5. 判断是否还需要 0-2 个辅助目录
6. 在对应目录页插入 wikilink
7. 保持目录页原有列表风格和局部排序
8. 只有在现有目录树无法容纳时，才考虑新增目录页
9. 如果笔记位于 `auto/...`，还要补同步 `article_index/`

如果只完成了前 3 步，而没有做目录判断和目录更新，就不算真正整合进系统。

## 目录选择的决策顺序

### 第一步：先问主问题

先回答：

> 如果半年后只从一个入口找这篇文献，我最可能从哪个专题页进去？

这就是主目录。

### 第二步：再问是否存在强辅助入口

只有当文章同时承担另一个明确专题节点角色时，才加入辅助目录。

例如：

- IMF By 驱动的高纬不对称性文章，可同时进入 `1.1 - 行星际磁场影响` 和 `2.17 - 南北半球差异`
- 以 CIR 为重点的磁暴文章，可同时进入 `2.6 - 磁暴` 和 `2.25 - CIR`

### 第三步：优先具体页

如果一个专题下已经有更细的叶子页，优先挂叶子页，而不是抽象父页。

## 目录页更新规则

### 列表风格

多数目录页使用编号列表：

`1. [[...]]`

插入新条目后，保持原有列表风格，不要突然改成无序列表、任务列表或表格。

### 排序

默认按发表年份从早到晚维护。

若同一年已有多篇但内部顺序不完全严格，则：

- 保留现有同年局部顺序
- 将新条目插入到该年份块的末尾

### 特殊目录页

少数页本身可能带有：

- 小节标题
- Todo 区
- 英文说明
- 占位条目

这些都属于已有系统的一部分，不应擅自清理。

### 其他行星识别的执行口径

`#其他行星/...` 和 `6 - 其他行星` 分类应基于“研究主体”判断，而不是宽泛沾边：

- 标题、首行标签、开头主总结里明确是某个非地球天体时，才归入该星球
- 只是在正文里偶然提到 `moon orbit`、`lunar mission`、`planetary science` 这类背景词，不足以归到 `其他行星`
- 卫星类对象按所属行星归类，例如木卫三归木星、土卫二归土星
